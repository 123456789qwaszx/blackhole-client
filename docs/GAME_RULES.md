# 블랙홀 키우기 — 게임 규칙 정리

작성일: 2026-09-24  
기준: 현재 대화에서 정리한 규칙과 최근 설계 판단

> 적을 처치해 플레이어는 구매 재화를 얻고 HQ는 성장한다. 플레이어는 전투 밖에서 업그레이드를 구매하며, 다음 전투의 스킬·적·출현 구성·보상에 구매 결과가 반영된다.

## 1. 문서의 범위

이 문서는 시스템의 의미와 책임을 공유하기 위한 문장 규칙이다. 구현 완료 보고나 기존 PLAN의 자동 변경을 뜻하지 않는다.

- **확정 규칙**: 대화에서 명확히 정한 동작과 경계.
- **현재 설계 방향**: 최근 설명과 설계 판단을 바탕으로 삼을 기준. 세부 콘텐츠와 수치는 별도로 정한다.
- **관찰·추정**: 사용자의 레퍼런스 플레이 경험에 기반한 내용. 레퍼런스 내부 구현을 검증한 사실이나 우리 게임의 확정 규칙으로 취급하지 않는다.
- **미정**: 아직 결정하지 않은 항목. 구현 편의를 위해 임의로 확정하지 않는다.

현재는 최대한 단순하게 만든다. 다만 현재의 단순함을 영구적인 제약으로 만들지 않는다. 미래 기능은 실제 요구사항이 생겼을 때 구현한다.

## 2. 전체 게임 흐름

1. 플레이어의 구매 상태와 전투 설정으로 새 전투를 준비한다.
2. HQ를 기준으로 적을 배치한다.
3. 적은 연결된 행동 규칙으로 움직인다. 현재는 HQ 주변 공전이다.
4. 플레이어의 패시브 스킬이 자신의 주기와 조건에 따라 공격한다.
5. 적의 HP가 0 이하가 되면 사망을 확정하고 보상을 반영한다.
6. 현재 설계 방향에서는 플레이어에게 Gold를 지급하고 HQ에는 성장 EXP를 반영한다.
7. 사망 효과가 있는 적은 해당 게임 효과를 발생시키고, 화면은 사망·흡수 연출을 보여 준다.
8. 성장 구간에 따른 시간 연장과 적 추가 공급은 현재 검토 중인 진행 방식이다.
9. 전투를 종료하고 업그레이드 화면으로 이동할 때 기존 적을 정리한다.
10. Gold로 업그레이드 노드를 구매한 뒤 다음 전투에 진입한다.

현재 종료 방식의 기준안은 제한 시간이 끝나면 즉시 종료하는 것이다. 멀티플레이 종료 방식은 별도로 검토한다.

## 3. 상태의 소유 관계

| 상태·정보 | 소유 주체 | 역할 |
|---|---|---|
| 위치 | HQ | 적 배치와 행동이 참조하는 공간 기준점 |
| 성장 EXP·레벨 | HQ | 현재 설계 방향에서 블랙홀 성장 진행도 |
| Gold·구매한 업그레이드 | 플레이어의 PlayerState | 구매 재화와 획득 상태 |
| 조준점 | 플레이어 | 현재 첫 스킬의 기준 위치 |
| 스킬 타이머·실행 수치 | 플레이어가 소유한 스킬 | 자동 공격 실행 |
| 종류별 기본 수치·특성 | 적 종류 정의 | 여러 개체가 공유하는 콘텐츠 |
| 현재 HP·위치·실행 수치 | 각 적 | 생성된 개체의 상태 |
| 남은 시간·전투 상태·진행 구간 | 전투 세션 및 진행 처리 | 진행과 종료 |
| 적 목록 | 적 관리 시스템 | 생성·생존·제거 관리 |
| 연출 경로·시간·View | Presentation | 결과의 시각적 표현 |

이 표는 책임의 구분이며 클래스나 파일 구성을 강제하지 않는다.

## 4. HQ — 블랙홀

### 확정 규칙

- 중앙 블랙홀은 본진이자 월드의 기준점인 HQ다.
- 적 생성과 행동은 HQ의 위치를 참조한다. 좌표 원점을 곧 HQ라고 가정하지 않는다.
- HQ와 플레이어는 서로 다른 존재다.
- HQ는 기준 정보를 제공하고, 생성·행동 계산은 각 시스템이 수행한다.
- 적이 블랙홀에 도착하는 연출은 처치·보상 확정 조건이 아니다.

### 현재 설계 방향

- 적 처치로 얻는 성장 EXP는 HQ에 반영한다.
- HQ는 EXP와 레벨을 가지며 성장을 시각적 크기 변화로 표현할 수 있다.
- HQ 레벨을 플레이어 공격력과 자동으로 연결하지 않는다.
- 특정 성장 구간의 시간 연장·적 공급은 진행 규칙에서 처리한다. HQ에 모든 기능을 넣지 않는다.
- 플레이어 레벨은 별도 필요가 확인되기 전까지 도입하지 않는다.

### 미정

- EXP 요구량과 성장 단계, 크기 변화의 공식.
- HQ 크기와 적 생성 최소 거리·공전 반경·카메라 시야의 관계.
- 다음 전투에서 HQ EXP·레벨이 얼마나 유지되는지.
- HQ HP·피격·파괴·패배 조건의 도입 여부.

## 5. 플레이어와 캐릭터

- 현재 플레이어는 1명이다. 플레이어가 전역에 하나뿐이라는 구조로 고정하지 않는다.
- 플레이어는 자신의 PlayerState와 스킬을 가진다.
- 플레이어와 캐릭터는 같은 개념이 아니다.
- 캐릭터는 개념상 존재하지만 현재는 투명하고 조작할 수 없다.
- 현재 캐릭터는 이동·피격·상호작용에 참여하지 않는다.
- 현재 캐릭터는 스킬 기준점이나 적의 추적 대상이 아니다.
- 캐릭터의 실제 게임플레이 기능은 향후 추가한다.
- 지금 책임이 없는 캐릭터를 위해 빈 클래스나 이동·HP 시스템을 미리 만들지 않는다.
- 장기적으로 최대 4인을 고려하되 네트워크·복제·로비·다인 UI는 현재 구현 범위에 넣지 않는다.

## 6. 패시브 스킬

- 플레이어의 스킬은 패시브 방식으로 발동한다.
- 첫 스킬은 기본 지급되며 조준점 주변 일정 영역을 일정 간격으로 공격한다.
- 현재 조준점은 마우스 포인터 위치에서 얻는다.
- 호스트가 입력을 플레이어의 조준점으로 전달한다. Player와 스킬 규칙은 마우스 장치를 직접 알 필요가 없다.
- 공격 틱마다 범위 안의 적 전체에 피해를 준다.
- 적이 없어도 주기 타이머는 계속 흐르고 빈 틱은 아무 효과 없이 지나간다.
- 화면의 원은 실제 공격 반경을 표시한다.
- 업그레이드로 피해량·반경·주기가 바뀔 수 있다.
- 마우스 기준은 첫 스킬의 특성이다. 모든 스킬이 마우스를 사용한다고 가정하지 않는다.
- 스킬 실행과 획득·강화는 별도 책임이다.
- 스킬은 적에게 피해를 요청한다. 다른 시스템의 HP를 직접 덮어쓰지 않는다.
- 피해 출처 Player를 기록하되 이를 멀티플레이 보상 수령 규칙으로 자동 해석하지 않는다.

미정: 구체적인 수치, 공격 원과 적 피격 범위의 겹침 판정, 조준점 부재 처리, 새 스킬 목록.

## 7. 적과 행동

- 행성처럼 보이는 대상은 게임 규칙상 적이다.
- 종류마다 기본 수치와 특성이 다를 수 있다.
- 각 적은 현재 HP·위치·생존 상태 등 자신의 실행 상태를 가진다.
- 같은 종류 정의를 공유하더라도 개체 상태는 공유하지 않는다.
- 적은 HQ 주변에 생성된다.
- 현재 행동은 플레이어에게 접근하는 것이 아니라 HQ 주변 공전이다.
- 행동 규칙은 적 본체와 분리하고 다른 행동으로 교체할 수 있어야 한다.
- 행동은 위치를 계산하고 적이 위치 상태를 가진다. 위치 원본을 중복 관리하지 않는다.
- 현재는 공전 하나만 구현한다. 상태 기계·행동 전환·추적은 요구사항이 생기면 추가한다.

## 8. 업그레이드와 실행 수치

### 구매 규칙

- 플레이어는 Gold를 소비해 업그레이드 노드를 구매한다.
- 구매 상태는 PlayerState에 기록하고 이후 전투에 반영한다.
- 구매는 획득 방법이다. 모든 구매 효과를 플레이어 스킬로 묶지 않는다.
- 현재 구매 구조의 기준은 선행 노드 조건과 Gold 가격이다.
- HQ 레벨에 의한 직접 해금 조건은 아직 도입하지 않는다.

| 구매 효과 | 적용 대상 |
|---|---|
| 공격 피해량 증가 | 스킬 실행 수치 |
| 공격 범위 증가 | 스킬 반경. 화면도 같은 값을 읽음 |
| 공격 주기 단축 | 스킬 실행 주기 |
| 적 크기 증가 | 적의 실행 수치 |
| 적 HP·보상 변화 | 적 수치·보상 계산 |
| 적 물량 증가 | 적 공급 구성 |
| 등장 종류·비율 변화 | 적 공급 구성 |
| 사망 특수 효과를 가진 적 등장 | 적 종류와 출현 구성 |

PlayerState는 구매 상태를 보관한다. 생성·공격·보상 계산은 각 시스템이 담당한다.

### 생성 시 계산 — 확정

- 적의 기본 정의와 실행 수치는 구분한다.
- 적의 실행 수치는 생성 시 기본 정의와 구매한 업그레이드를 반영해 확정한다.
- 업그레이드 화면에 들어가기 전에 기존 적은 정리된다.
- 구매 효과는 이후 생성되는 적부터 적용한다. 살아 있는 적에 구매 보정을 다시 적용하는 기능은 필요하지 않다.
- 별도의 전투 중 일시 효과는 실제 요구사항이 생겼을 때 정의한다.

### 크기와 질량 — 현재 설계 방향

- 크기와 질량은 별개의 의미로 취급한다.
- 크기는 외형과 피격 범위에 영향을 주는 방향이다.
- 질량 증가는 HP와 보상이 함께 증가하는 의미로 검토한다.
- 독립적인 질량 수치와 환산 공식은 미정이다. HP·보상 보정으로 충분하면 별도 계산 체계를 만들지 않는다.
- 적이 커지거나 많아지는 것은 난이도 증가뿐 아니라 더 많이 벌기 위한 성장 요소가 될 수 있다.

## 9. 적 공급과 진행 구간

### 현재 설계 방향

- 적 공급은 전투 시작 시 배치와 HQ 성장 구간 도달 시 추가 공급을 우선 검토한다.
- 일정 시간마다 적이 생성되는 방식은 현재 확정 규칙이 아니다.
- 공급 규칙은 언제·어떤 종류를·얼마나 추가할지 결정한다.
- 적 생성은 전달받은 종류·수량으로 HQ 기준 위치에 개체를 만든다.
- 진행 구간은 시간 연장·적 추가·이후 출현 구성 변경·전환 연출을 연결할 수 있다.
- 일반 레벨업과 특정 성장 구간 도달을 구분한다. 모든 레벨업이 같은 효과를 갖는다고 가정하지 않는다.

### 레퍼런스 관찰·추정

- 시작 시 적이 배치되고 블랙홀 성장에 따라 시간이 늘어나며 적이 추가되는 것으로 관찰됐다.
- 진행에 따라 적 종류가 추가되지만 레벨·구매 노드 등 실제 조건은 미확인이다.
- 특정 구간에서 주변 천체를 전부 끌어당기는 효과가 관찰됐다.
- 이 효과가 실제 전체 처치인지 전환 연출인지, 추가 보상·EXP를 발생시키는지는 미확인이다.

우리 게임의 공급 트리거·수량·구간 구성은 별도로 확정한다.

## 10. 피해·사망·보상

- HP가 0 이하가 되는 순간 사망이 확정된다.
- 같은 적의 사망과 보상은 한 번만 처리한다.
- 사망한 적은 더 이상 이동·피해·대상 선택에 참여하지 않는다.
- 사망 시 보상을 계산·반영한다. 흡수 연출 완료를 기다리지 않는다.
- 현재 설계 방향에서는 Gold는 플레이어에게, 성장 EXP는 HQ에 반영한다.
- 사망 후 화면에 남아 있는 것과 게임 규칙상 살아 있는 것은 별개다.
- 전투 공간 정리를 위한 제거를 보상이 발생하는 처치와 자동으로 동일시하지 않는다.
- 현재는 단일 플레이어에게 Gold를 지급한다. 다인 보상 분배는 미정이다.

## 11. 사망 특수 효과 — 채택할 설계 기준

사용자가 요청한 설계 판단에 따라, 특정 적의 죽음으로 발동하는 폭발·전기·레이저 등은 적의 사망 특성으로 다룬다. 예시 효과를 모두 지금 구현한다는 뜻은 아니다.

| 구분 | 발동 계기 | 역할 |
|---|---|---|
| 플레이어 패시브 스킬 | 자신의 주기·조건 | 플레이어 자동 공격 |
| 적 사망 효과 | 해당 적의 사망 | 주변 피해·연쇄 공격 등 게임 효과 |
| 사망 Presentation | 처리된 사망 결과 | 폭발·번개·흡수의 시각적 표현 |

- 적 종류 정의가 사망 효과를 지정한다.
- 적은 자신의 사망을 한 번 확정한다.
- 전투 처리가 사망 효과의 대상과 피해를 계산한다.
- 보상 처리가 해당 사망의 보상을 한 번 반영한다.
- 화면은 결과를 표현한다. 연출의 충돌이나 완료 여부로 피해를 결정하지 않는다.
- 사망 효과로 다른 적을 처치할 수 있으며 그 적도 같은 사망 절차(보상 1회, 사망 기록)를 따른다.
- **사망 효과는 사망 효과를 가진 적에게 피해를 주지 않는다.** 그래서 사망 효과가 다른 사망 효과를 부르는 연쇄는 없다(2026-09-24 확정, 레퍼런스와 같다).
- 한 단계에 생긴 사망 효과는 대기열에 넣어 순서대로 처리한다. 적끼리 사망 처리를 재귀 호출하지 않는다.
- 첫 특수 효과부터 적 본체 밖에 구현하되 범용 효과 프레임워크는 미리 만들지 않는다.

기본 순서: 사망 확정 및 대상 제외 → 보상 반영과 효과 기록 → 효과 피해 처리 → 새 사망 처리. 화면은 이 결과를 표현한다.

첫 효과는 전기 연쇄 번개다(2026-09-24 확정, M7). 수치는 콘텐츠 값이다.

미정: 연쇄 처치 출처(M7은 [임시]로 효과를 일으킨 적을 죽인 Player를 기록한다), 성장 구간 전환·시간 종료와 효과 처리가 겹칠 때의 순서(M7은 [임시]로 한 단계의 효과 대기열을 모두 처리한 뒤 성장과 종료를 판정한다), 두 번째 이후 효과.

## 12. Presentation과 공간

- 공격 원은 실제 스킬 반경을 읽어 표시한다.
- 흡수는 사망 위치에서 HQ로 이동한 뒤 View를 제거하는 연출이다.
- 연출이 느려지거나 생략돼도 보상 결과는 바뀌지 않는다.
- 한 화면 프레임에 여러 사망이 발생해도 중간 사망 결과를 놓치지 않아야 한다.
- 시각적 크기 변화와 실제 생성 공간 변화는 구분한다.
- 커진 HQ와 겹치지 않게 실제 생성 위치를 바꾸면 그 부분은 생성 규칙이다.
- HQ 외형·공간 값의 관계는 기획으로 정한다. 스프라이트 크기가 게임 규칙의 원본이라고 미리 가정하지 않는다.

## 13. 종료와 재시작

- 전투 시작·진행·종료와 다음 전투 조립을 구분한다.
- 현재 기준안은 제한 시간이 끝나면 즉시 종료하는 것이다.
- 종료 조건 판단과 적·화면 정리는 별도 책임으로 둔다.
- 업그레이드 화면 진입 시 기존 적은 남기지 않는다.
- 새 전투는 구매 상태를 반영하되 이전 적의 HP·위치·스킬 타이머가 섞이지 않도록 조립한다.
- 구매 상태를 전투 사이에 유지하는 것과 앱 종료 후 영구 저장하는 것은 별도 결정이다.
- 멀티플레이에서 같은 종료 조건을 사용할지는 미정이다.

미정: 종료와 공격 틱이 겹치는 순간의 순서, 진행 중인 연쇄 효과와 남은 흡수 연출의 처리, 일시정지 시 연출 처리.

## 14. 해금과 경제 밸런스

- 선행 노드 해금 조건과 가격을 지불할 수 있는지는 별개다.
- 구간별 예상 수입과 가격을 맞추면 HQ 레벨 조건 없이도 비슷한 시점에 새 능력을 구매하게 만들 수 있다.
- 레퍼런스가 이 방식으로 구매 시점과 성장 구간을 맞췄다는 설명은 현재 추정이다.
- 수입·공격력은 조준 효율과 구매 순서에 따라 달라지므로 예상 범위로 검토한다.
- 관찰한 10만·50만·100만 등의 금액을 우리 게임 임계값으로 확정하지 않는다.

## 17. 한 문장 기준

> HQ는 공간과 성장의 기준을 제공하고, 플레이어는 업그레이드를 소유하며, 적은 자신의 상태와 교체 가능한 행동·사망 특성을 가진다. 게임 결과는 규칙에서 확정하고 화면은 그 결과를 표현한다.


## 18. 기존 구현의 유지 사항

M3에서 확인한 첫 공격 틱 0초, 빈 틱의 연속 진행, Player별 조준점·스킬 독립성은 유지한다. 현재 중심 기준 피격 판정과 조준점 부재 시 빈 틱 처리는 임시 구현이며 확정 게임 규칙과 구분한다.

이 문서는 최근 대화를 반영한 저장소의 규칙 기준이다. 구 가이드와 완료된 M0~M3 기록은 당시 판단의 이력으로 읽는다.
