# 블랙홀 게임 규칙 정리

출처: 사용자 설계 가이드 `BLACKHOLE_GAME_SYSTEM_DESIGN_GUIDE.md`(2026-09-24)와 같은 날의 질문·답변. 이 문서는 두 자료를 시스템 후보별로 다시 묶은 것이며, 새 규칙을 더하지 않는다. 가이드와 다르게 읽히는 곳이 있으면 가이드가 우선이다.

한 줄 기준: **지금은 최대한 단순하게 만든다. 다만 지금의 단순함을 게임 전체의 영구적인 제약으로 만들지는 않는다.**

- 지금 1명인 Player를 "게임에 하나뿐인 Player"로 만들지 않는다(Players.Count = 1일 뿐이다).
- Character 1종이라고 Player와 Character를 같은 것으로 보지 않는다.
- Orbit 하나라고 Orbit을 Enemy 본체에 넣지 않는다.
- 첫 Skill이 마우스 기반이라고 모든 Skill이 마우스 기반이라고 가정하지 않는다.
- 미래 확장을 고려하는 것이 미래 기능을 먼저 만드는 것은 아니다. 네트워크, 캐릭터 선택, AI 상태 기계, 범용 능력 프레임워크는 만들지 않는다.

## 1. 현재 게임 흐름

```text
                 HQ (중앙 블랙홀) ── 월드 기준점
                  ├─→ Enemy 출현 위치의 기준
                  └─→ Enemy 행동의 기준 (현재: HQ 주위 Orbit)

Player ─ 첫 Passive Skill
          소유 Player의 마우스 위치 = 중심
          → 반경 → 공격 주기마다 → 원 안의 Enemy 전부에 피해
                                         ↓
                                     HP <= 0
                                         ↓
                                  Death 확정
                              ┌─────────┴─────────┐
                     Gold / EXP 계산·지급      (Presentation)
                                            블랙홀로 빨려드는 연출
                                                    ↓
                                                View 제거
```

연출이 느려지거나 생략돼도 보상은 바뀌지 않는다. View가 사라지는 시점과 Gameplay의 Death 시점은 다를 수 있다.

## 2. 시스템 후보별 규칙

각 항목은 확정된 규칙, 미정, 개념상 누가 가지는 값인가, 다른 후보와의 접점 순서로 적는다. "누가 가지는가"는 개념 수준이며 클래스 구성을 정하지 않는다.

### Player / PlayerCharacter / Character

- **확정**
  - Player는 게임 안의 사용자 단위다. 지금은 1명이다.
  - PlayerCharacter는 존재하지만 투명하다. 위치, 이동, HP, 피격, 외형이 없고, Skill의 기준점도 아니며 Enemy가 추적하지도 않는다.
  - Character는 1종이다. 선택이 없고 Skill Tree도 고정된 하나다.
- **미정**: PlayerCharacter가 실제로 전투에 참여하는 방식, Character별 구체적인 차이.
- **장기 방향**: 최대 4인, Player별 Character, Character별 외형·특성·Passive Skill·Skill Tree.
- **누가 가지는가**: Player마다 자신의 상태(PlayerState)를 가진다. 4인을 고려하므로 각 Player의 현재 상태는 서로 구별되어야 한다.

### HQ (블랙홀)

- **확정**
  - 중앙 블랙홀은 월드의 기준점이자 HQ다.
  - Enemy 출현과 Enemy 행동이 HQ를 참조할 수 있다. HQ가 Enemy AI를 직접 실행하지는 않는다.
  - **HQ 성장은 핵심 요소다.**
- **미정**
  - HQ HP, 피격, 파괴, 그로 인한 패배 조건
  - 성장 수치, 그리고 성장한 크기·영향력이 출현 거리나 Orbit 반경, Enemy 수치에 영향을 주는지
- **누가 가지는가**: HQ의 성장 상태는 HQ가 가진다. Player와 HQ는 다른 존재다.
- **접점**: 출현과 Enemy 행동이 HQ의 위치(와 필요하면 성장 상태)를 읽는다.

### Enemy

- **확정**
  - 행성처럼 보이는 오브젝트는 게임 규칙상 Enemy다.
  - 종류별로 서로 다른 객체이며, 수치(HP, 이동 속도, 크기, 보상 Gold/EXP 등)와 특성이 다르다. 행동 AI나 고유 능력까지 달라질 수 있는 게임을 전제로 한다.
  - 기본 수치(종류 정의)와 실제 실행 수치(Runtime Stat)는 같은 개념이 아니다. Runtime Stat은 진행도, PlayerState, 획득 능력 등의 보정을 받을 수 있다.
  - 공통 생명주기: Alive → 피해 → HP <= 0 → Dead. HP가 0 이하가 되는 순간 Death가 확정된다.
- **미정**
  - 난이도가 오르는 방식, Player 능력이 Enemy를 약하게 만드는 방식, 둘을 함께 쓰는지
  - Runtime Stat을 출현 때 한 번 계산하는지, 살아 있는 Enemy에게도 즉시 반영하는지
  - 종류별 고유 능력(보호막, 분열, 폭발 등)과 종류별 사망 효과
- **개념 흐름**: 기본 정의 + 진행 상태 + PlayerState·능력 보정 → Runtime Stat.
- **누가 가지는가**: HP 같은 개체 상태는 각 Enemy가 가진다. 종류 정의는 여러 Enemy가 공유한다.

### Enemy 행동 (AI)

- **확정**
  - 행동은 Enemy 본체에서 분리한다. 다른 행동이나 상황별 전환이 필요해져도 Enemy 자체를 뜯지 않게 하기 위해서다.
  - 지금 구현할 행동은 **HQ 주위 Orbit** 하나다.
- **지금 만들지 않는 것**: AI 상태 기계, 실행 중 행동 전환, 조건 평가기. 실제 기획(예: 체력이 낮으면 돌진)이 생길 때 도입한다.
- **접점**: HQ의 위치를 읽는다.

### 출현 (Spawn)

- **확정**: Enemy는 HQ 주변에 생성된다. 출현 위치는 HQ를 기준으로 계산한다.
- **미정**: 주기, 수량, 종류 구성, HQ 성장에 따른 거리 변화.

### Passive Skill

- **확정**
  - 공격 수단은 Passive Skill이다. 버튼을 눌러 쓰는 액티브 스킬을 기본으로 가정하지 않는다.
  - Passive Skill은 각자 자신의 발동 조건과 주기를 가지고 자동으로 실행된다.
  - **첫 Skill**: 소유 Player의 마우스 위치를 중심으로 원형 범위를 가진다. 공격 주기마다 범위 안의 Enemy를 전부 공격한다.
  - 원은 실제 공격 범위를 보여 주는 Presentation이다. 공격 범위와 원의 크기는 같은 것을 뜻한다.
  - Skill의 성장은 주로 수치 변화다(피해량, 반경, 공격 속도·주기, 효과 강도).
  - Skill이 실행되는 구조와 Skill을 얻는 구조는 따로 생각한다.
- **미정**: 두 번째 이후 Skill을 얻는 방법(레벨업, 강화, 별도 시스템 등).
- **장기 방향**: Skill 기준점은 마우스 외에도 PlayerCharacter 주변, HQ 주변, 가장 가까운 Enemy, 화면 전체, 특정 방향 등이 될 수 있다.
- **누가 가지는가**: Skill은 소유 Player에 속한다. 공격 주기와 성장 상태는 그 Player의 Skill이 가진다.

### 사망과 보상 (Combat / Death / Reward)

- **확정**
  - Death가 확정되는 순간 Gold와 EXP를 계산해 지급한다.
  - 블랙홀로 빨려 들어가는 것은 보상 조건이 아니라 사망 연출이다.
- **미정**: 종류별 추가 사망 효과.

### Player 성장과 경제 (PlayerState)

- **확정**: Level과 EXP가 존재한다.
- **미정**
  - 레벨업의 결과(능력 선택인지, 자동 성장인지)
  - Gold의 사용처. 원작처럼 Upgrade에 쓰일 가능성이 높지만, 판 안 강화인지 영구 성장인지 등 경제 구조는 정하지 않았다
  - PlayerState의 수명, 판 안 상태와 영구 진행 데이터의 경계
- **PlayerState의 예상 내용**: Level, EXP, 진행도, 획득 능력, Passive Skill 성장 상태, 각종 보정값. 지금은 필요한 것만 둔다.

### 세션 (한 판)

- **현재 후보**: 원작처럼 시간제.
- **미정**: 최종 종료 조건이 시간인지, HQ 파괴를 포함하는지.

## 3. 규칙을 합쳐 보면 생기는 질문

위 규칙들은 각각은 정해져 있지만, 서로 맞물리는 곳에서 아직 답이 없는 질문이 생긴다. 지금 결정할 필요는 없지만, 정하지 않으면 구현이 전역 가정을 몰래 넣게 되는 곳이다.

1. **HQ는 무엇으로 성장하는가?** 흡수는 연출이므로 "빨려 들어가서 성장"은 규칙이 될 수 없다. 성장의 계기는 Enemy Death, 강화 구매, 시간 등 연출과 무관한 사건이어야 한다.
2. **보상은 누가 받는가?** 최대 4인을 고려하면 Death 때의 Gold/EXP 수령자(마지막 타격자, 전원 공유, 기여도 등)가 필요하다. 1인이어도 "수령자를 정하는 자리"를 두는 것이 전역 PlayerState를 피하는 방법이다.
3. **Enemy 수치를 바꾸는 PlayerState는 누구의 것인가?** 4인이면 공유 진행도로 보정하는지, 개인 능력으로 보정하는지, 한 Enemy에 여러 Player의 보정이 겹치는지가 문제가 된다.
4. **마우스는 누구의 입력인가?** 첫 Skill의 기준점은 "소유 Player의 마우스"다. 4인에서는 Player마다 입력이 따로 있어야 하므로, 입력도 Player에 속하는 것으로 둔다.

## 4. 현재 Reference와 다른 점

Reference(`Assets/BlackHole`)는 이 규칙이 정해지기 전에 임의로 만든 예제다. 아래는 이 문서와 어긋나는 부분이다.

| 주제 | Reference | 이 문서의 규칙 |
|---|---|---|
| 보상 시점 | 흡수 확정 때 지급(Defeated → Absorbed) | Death 확정 때 지급 |
| 흡수 | 게임 규칙(흡수 반경, 흡수 전이, 사망 후 낙하 속도) | 사망 연출. 규칙에서 빠짐 |
| 스킬 | 누르는 액티브 스킬 2개, 쿨다운, 빈 조준 규칙, 당김 효과 | 자동 Passive. 첫 Skill은 마우스 중심 주기 범위 피해 |
| 조준 원 | 시전 순간의 연출 | 공격 범위를 계속 표시 |
| Player | 개념 없음. 스킬·재화·강화가 판(Playfield)에 하나씩 박혀 있음 | Player 단위가 있고, Player마다 상태가 구별됨(지금 1명) |
| HQ | 좌표 원점일 뿐이고, "블랙홀 상태"는 질량 성장만 가짐 | 월드 기준점이 되는 대상. 출현·행동이 HQ를 참조 |
| HQ 성장 | 흡수한 질량 → 흡수 반경(임의 공식) | 성장은 핵심이지만 계기와 영향은 미정 |
| Enemy 수치 | 정의 값을 그대로 사용 | 기본 정의와 Runtime Stat을 분리(보정 방식은 미정) |
| 재화 | Credits만 있고 강화 구매에 씀 | Gold와 EXP·Level. 사용처와 레벨업 결과는 미정 |
| 강화·스킬트리 | Credits로 구매, 트리 AND 규칙 | Skill Tree는 1개 고정. 구조와 획득 방식은 미정 |
| 한 판 | 60초 고정 | 시간제는 후보일 뿐 |

맞는 부분도 있다. Enemy 행동을 본체에서 분리한 것, 정의와 실행 상태를 나눈 것, 화면이 게임 상태를 읽기만 하는 것, AI 상태 기계나 범용 프레임워크를 만들지 않은 것은 이 문서의 원칙과 같다.
