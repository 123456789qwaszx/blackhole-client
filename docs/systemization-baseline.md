# 시스템화 기준 동작 (S0)

기준 커밋: `80549cb`. 이후 구조 변경은 아래 기준을 유지해야 한다. 값이 바뀌면 의도한 규칙 변경인지 먼저 확인하고, 구조 변경과 같은 커밋에 섞지 않는다.

## 플레이 기준

- 60초 시간제 판. 대상 `shard`(HP 12, 보상 2)와 `heavy`(HP 30, 보상 5)가 0.8초마다 교대로 반경 5.5에 출현하고, 최대 32개다.
- 스킬: `focused-strike`(쿨다운 0.35, 조준 반경 0.9 안의 가장 가까운 대상 하나에 피해 14), `gravity-pulse`(쿨다운 2, 반경 2.4 안의 모든 대상에 피해 9와 당김 0.8).
- 사망한 대상은 중심으로 떨어지고 흡수될 때만 보상을 받는다. 보상은 질량과 재화를 같은 양만큼 올린다.
- 강화: 비용 6 × (다음 단계), 최대 5단계, 단계당 피해 배율 +0.35.
- 조작: 마우스 조준, 1/2 시전, U 강화, P 일시정지·재개, R 재시작.
- 한 프레임 순서: 재시작 요청(있으면 그 프레임 종료) → 일시정지 전환 → Advance → 시전·강화 요청 → 화면 갱신.

## 자동 기준 (`CoreContracts`)

| 사례 | 고정하는 것 |
|---|---|
| 기존 13개 계약 | 사망과 흡수 구분, 보상 1회, 스킬 선택 차이, 쿨다운/빈 조준, 강화 실패, 일시정지, 종료, 재시작, 정의 검증, 확장, 생성 상한, 핵심 흐름 |
| `BaselineAtCoarseFixedStep` / `BaselineAtFrameFixedStep` | 같은 스크립트 입력과 고정 간격(0.1초, 1/60초)에서 6초 시점과 60초 종료 시점의 수치 |
| `FinalFrameIsClippedToTimeLimit` | 마지막 프레임이 제한 시간을 넘겨 진행하지 않음 |
| `CooldownExpiresBeforeSameFrameRequest` | 쿨다운은 Advance 안에서 줄고, 같은 프레임 요청은 그 뒤에 판정됨 |
| `AbsorptionHappensInStepReachingRadius` | 흡수 반경에 닿은 단계에서 흡수·보상·목록 제거가 함께 끝남 |

수치 기준은 같은 콘텐츠·입력·Advance 간격에서만 보장된다. 간격이 달라지면 중간 상태가 달라질 수 있고(6초 시점 HP 합계 6.2 대 0), 최종 수치가 같은 것은 생성량이 결과를 제한하기 때문이다. 수치 기준 하나가 세부 계약을 대신하지 않는다.

## 정의 밖에 있는 상수

게임 규칙 수치, 실행 설정, 표현 값은 서로 다른 주인에게 둔다. 모든 값을 콘텐츠 데이터로 옮기지 않는다.

| 값 | 기준 시점 위치 | 분류 | 목표 주인 | 단계 |
|---|---|---|---|---|
| 흡수 반경 `0.65 + min(질량, 50) × 0.012` | `GrowthState.AbsorptionRadius` | 게임 규칙 | 블랙홀 정의 | S5 |
| 강화 비용 증가 `비용 × (단계 + 1)` | `GrowthState.NextUpgradeCost` | 게임 규칙 | 강화 정의 | S5 |
| 궤도 최소 여유 `흡수 반경 + 0.8` | `TargetState.Move` | 게임 규칙 | 이동 규칙 정의 | S3 |
| 사망 후 낙하 속도 `4` | `TargetState.Move` | 게임 규칙 | 이동·생명주기 규칙 | S3 |
| 출현 각도 간격(황금각 `2.399963`) | `SpawnSchedule` | 게임 규칙(배치) | 생성 배치 규칙 | S3 |
| 빈 조준은 쿨다운을 소비하지 않음 | `SkillLoadout.TryCast` | 규칙 정책 | Skill | S4 |

| 대상 크기·색, 카메라 크기·배경 | `ReferenceWorldView`, `ReferenceGameController` | 표현 | 표현 정의 | S7 |
