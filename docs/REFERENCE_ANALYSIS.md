# REFERENCE ANALYSIS — A Game About Feeding A Black Hole

정리일: 2026-09-24 · 최신화: 2026-09-28 (천체 생성·파괴 분석을 합치고, 8절 비교를 `feature/블랙홀성장도` 기준으로 고침)

대상: Aarimous·Thornity의 **A Game About Feeding A Black Hole**

분석 중심: 기본 플레이와 성장·업그레이드 구조, 천체가 판에 생기고 사라지는 형식. 다른 모드·데모의 내용은 구분한다.

## 1. 이 문서를 읽는 방법

이 문서는 원작을 분석한 자료이며 우리 게임의 명세가 아니다. 구현해야 할 규칙은 [GAME_RULES_MVP](GAME_RULES_MVP.md), 판 구성과 보상은 [BATTLE_COMPOSITION_PLAN](BATTLE_COMPOSITION_PLAN.md), 스킬과 노드 트리는 [SKILL_TREE_PLAN](SKILL_TREE_PLAN.md), 성능 기준은 [BLACKHOLE_PERFORMANCE_DESIGN_PRINCIPLES](BLACKHOLE_PERFORMANCE_DESIGN_PRINCIPLES.md)를 따른다. 사용자의 원작 플레이 관찰 중 색 등급·황금·이정표·노드 값은 BATTLE_COMPOSITION_PLAN 2절에, 트리 모양은 SKILL_TREE_PLAN 4.1에 있다.

공식 페이지·개발자 답변을 재확인하고, 기존 문서에 기록된 플레이 관찰을 구분하여 재구성했다. 원작의 내부 소스 코드를 확인한 분석은 아니다.

| 근거 표시 | 의미 |
|---|---|
| 공식 | 상점·개발자 페이지·패치 노트에 직접 적힌 내용 |
| 개발자 답변 | Steam 토론에서 개발자가 직접 설명한 동작·의도 |
| 기존 플레이 관찰 | 이전 분석 문서에 기록된 사용자 관찰. 이번 조사에서 직접 재현하지 않음 |
| 사용자 플레이 관찰 | 프로젝트 사용자가 원작을 직접 플레이하며 확인해 알려 준 내용. 날짜를 함께 적음 |
| 플레이어 보고 | 댓글·리뷰·공략의 설명. 버전·환경에 따라 다를 수 있음 |
| 분석 | 확인된 자료를 바탕으로 한 해석. 원작의 내부 구조를 뜻하지 않음 |
| 미확인 | 현재 근거만으로 규칙·수치를 확정할 수 없음 |

- 원작의 "천체(object)"는 소행성·행성·별·달·혜성 등 파괴 대상 전체이며 우리 게임의 Enemy에 해당한다.
- 메인 모드가 아닌 모드(Zen, The Line, Electric Moons, Roguelike, Orb Breaker)의 근거는 모드를 함께 적는다. 모드 규칙을 메인 모드 규칙으로 옮기지 않는다.
- 개발자 답변이라도 사용자 플레이 관찰과 충돌하면 그 사실을 적고, 현재 동작의 근거로 쓰지 않는다.
- 원작 자료의 "session"은 우리 게임의 판(한 번의 전투)이다. 블랙홀 Level은 매 판 0부터이고, 판을 넘어 이어지는 것은 성장도다(사용자 플레이 관찰, 2026-09-28).

이전 분석 기록은 [기준 커밋의 REFERENCE_ANALYSIS](https://github.com/123456789qwaszx/blackhole-client/blob/d0e8fc9159b9b84d34c0bcf2c1a8dfb530157e0b/docs/REFERENCE_ANALYSIS.md)에 남아 있다. 그 문서의 마일스톤·옛 GAME_RULES 절 번호는 현재 명세 근거로 사용하지 않는다.

## 2. 게임의 중심 경험

**천체를 부수어 블랙홀을 성장시키고, 반복 플레이 사이의 업그레이드로 파괴 효율과 전투 규모를 키우는 짧은 인크리멘털 게임**이다.

공식 상점은 소행성·행성·별을 파괴하여 블랙홀에 물질을 공급하는 게임으로 소개한다. Steam 출시일은 2025-12-15다.[R1] 개발자의 itch.io 페이지는 정식판의 메인 모드를 약 2~3시간, 업그레이드를 200개 이상으로 소개한다. itch.io에서 실행하는 것은 데모다.[R2]

### 두 가지 반복

| 반복 | 플레이 흐름 | 성장의 의미 | 근거 |
|---|---|---|---|
| 한 판 안 | 조준·파괴 → 물질 공급 → 블랙홀 성장 → 추가 파괴 기회 | 지금 진행 중인 전투의 확장 | 기존 플레이 관찰, R2의 성장·시간 관련 보고 |
| 판 사이 | 전투 → 업그레이드 화면 → 구매 → 다음 전투 | 이후 전투의 효율·구성 변화 | R5의 개발자 설명과 플레이어 보고 |

**분석:** 전투 중에는 "어디를 먼저 부술까", 전투 사이에는 "다음에는 무엇을 강화할까"로 관심이 이동한다. 블랙홀의 성장은 두 반복에 나뉜다 — 판 Level은 판 안에서 0부터 오르고, 그 판이 목표 Level에 닿으면 판 밖의 성장도가 올라 다음 판의 색과 Level 표를 정한다(사용자 플레이 관찰, 2026-09-28).

## 3. 전투 중 시스템 분석

### 3.1 조작과 Breaker

| 항목 | 관찰·자료 | 확실성 |
|---|---|---|
| 주 조작 | 커서를 움직여 공격 위치를 바꾼다 | 기존 문서의 플레이어 보고 |
| 공격 방식 | 커서 주변 원이 주기적으로 피해를 주며 반복 클릭 중심이 아니다 | 기존 문서의 플레이어 보고, 정확한 판정 재확인 필요 |
| 강화 축 | 피해량·반경·공격 속도·치명타 | 기존 분석의 공략 정리. 전체 노드 목록 미확인 |
| 클릭 | 마우스 버튼은 Breaker에 영향이 없고, 게임이 클릭을 "쓸모없는 수동 클릭"으로 센다 | 플레이어 보고 [R11] |
| 관통 레이저 | 화면 바깥의 무작위 지점에서 커서를 향해 얇은 예고선을 긋고, 굵어지며 화면을 가로질러 경로의 적에게 피해를 준다. 예고 순간 방향 고정, 발사 순간 1회 피해, 주기마다 1발, 트리에서 해금(별 단계) | 사용자 플레이 관찰 (2026-09-25 · 26). 천체 효과 "레이저 별"과의 관계 미확인 |
| 미확인 | 첫 공격 시점, 빈 공격의 처리, 물체 중심/외곽 판정, 긴 프레임 처리 | 내부 규칙으로 단정하지 않음 |

**분석:** 공격 타이밍보다 위치 선택에 조작 부담을 모은다. 공격 범위·피격 반응이 명확해야 플레이어가 자신의 조작과 파괴 결과를 연결할 수 있다.

우리 게임의 "첫 Tick 0초", "빈 Tick 소비", "범위 내 전부 피해"는 우리 명세다. 원작의 자동 공격 관찰만으로 이 세부 규칙까지 입증되지는 않는다.

### 3.2 천체와 파괴

| 대상 | 확인된 내용 | 근거 |
|---|---|---|
| 소행성·행성·별 | 공식 소개의 기본 파괴 대상. 각각 여섯 색 등급이 있다 | 공식 R1, 사용자 플레이 관찰 (2026-09-26) |
| 혜성과 기타 천체 | 정식판에 포함된다고 소개 | 공식 R2 |
| 전기 천체 | 주변에 연쇄 번개를 발생시킴 | 개발자 답변 R3 |
| 황금 천체 | 파괴 시 획득 금액을 강화. 소행성에만 붙는 특성 | 개발자 답변 R3, 사용자 플레이 관찰 |
| 방사능 천체 | 파괴 후 구름이 남아 주변에 효과를 주는 것으로 보고됨. 정식판에서 황금 소행성으로 바뀜 | 데모 플레이어 보고 R2, BATTLE_COMPOSITION_PLAN G5 |
| 달 | 파괴하면 일정 시간 Breaker가 강화됨. 다른 천체에 피해를 주지 않으며, 지속 시간은 업그레이드 대상 | 플레이어 보고 R7·R9 |
| 혜성 | 커서 공격이 항상 치명타가 되는 강화를 줌. 닿기만 해도 부서진다 | 플레이어 보고 R8, 사용자 플레이 관찰 |
| 레이저 별·초신성 | 효과를 가진 별. 초신성의 피해는 강화로 "100%"까지 올라간다고 보고되며, 초신성끼리는 피해를 주지 않음 | 플레이어 보고 R7·R8. 피해 공식 미확인 |

**분석:** 천체 효과의 결과는 피해만이 아니다. 달·혜성은 다른 천체를 공격하지 않고 플레이어의 공격 수치를 일정 시간 바꾼다. 효과를 정의할 때 "결과"를 피해 하나로 고정하지 않아야 한다.

### 3.3 성장과 공급

기존 플레이 관찰에는 다음 내용이 기록되어 있다.

- 블랙홀이 성장하면 소행성이 추가되고 시간이 늘어난다.
- 성장 시 추가되는 소행성 수를 늘리는 업그레이드가 초반에 있다.

데모 댓글에도 블랙홀 성장 때 시간이 증가한다는 보고가 있다.[R2] 개발자는 천체가 다시 생성될 확률이 있다고 설명한다.[R4]

| 공급 계기 | 근거 수준 | 확인 범위 |
|---|---|---|
| 전투 시작 | 기존 분석 기록 | 기본 배치 수·분포·종류 비율 미확인 |
| 블랙홀 성장 | 기존 플레이 관찰 | 성장 시 추가 공급. "성장 때 소행성 확률" 노드가 25%에서 100%까지 오른다(사용자 플레이 관찰, 2026-09-27) |
| 천체 파괴와 재등장 | 개발자 답변 R4 | 재등장 가능성은 확인, 대상 종류·확률·자식 효과 계승은 미확인 |
| 시간 주기 생성 | 미확인 | 조사 근거에서 확정하지 못함. 원작 전체에 없다고 단정하지 않음 |

**분석:** 성공에 공급과 시간을 연결하면 파괴가 다음 파괴 기회를 만든다. 다만 이벤트 기반이라는 사실만으로 전체 개체 수가 제한되거나 로그식으로 증가한다고 결론 내릴 수 없다.

**이정표(Milestone).** 성장도가 정해진 값(소행성 단계는 10)에 닿으면 이정표다. 그 판은 성장하기 충분한 Level에 닿는 순간 끝나고, 전체가 빨려 들고, 고정 보상을 준다. 그 뒤 다음 종류(행성)가 나오기 시작한다. 일반 Level업은 시간·공급을 늘린다(사용자 플레이 관찰, 2026-09-27 · 28. 공략의 이정표 7개와 Level 범위도 성장도로 읽으면 맞다 — BATTLE_COMPOSITION_PLAN 2·8절).

### 3.4 물질 흡수와 성장의 시점

데모에는 파편이 주변을 돌기만 하여 블랙홀이 성장하지 않는다는 보고가 있고, 개발자도 웹 빌드의 문제를 언급했다.[R2]

사용자 플레이 관찰(2026-09-25)로는 **보상이 조각이 빨려 들기 전에 이미 지급된다**(5.1). 흡수 움직임은 파괴 결과가 성장으로 이어짐을 보여 주는 피드백이다. 이정표 때 모두 빨려 드는 것도 Level·성장도에 반영되지 않는다(2026-09-27).

**분석:** 우리 게임은 사망 순간 결과를 확정하고 흡수는 별도 연출로 둔다. 원작의 내부 동작을 그대로 복제한다는 설명은 사용하지 않는다.

### 3.5 한 판의 종료

전투와 업그레이드 화면을 반복하는 흐름은 개발자 설명과 플레이어 보고에서 확인된다.[R5] 판은 기본 14초이고, 판 시간 노드가 기본 시간을 늘린다(별 단계에서 39초). 판은 시간 종료·End Session·이정표 도달로 끝난다. 모두 부수면 조기 종료 버튼이 나온다(5.1).

마지막 순간의 성장과 타임아웃의 우선순위는 별도 재현이 필요하다. 우리의 "같은 Step의 성장·연장을 반영한 뒤 종료"와 "Cleanup은 처치가 아님"은 우리 팀의 확정 규칙이다.

### 3.6 소리와 피드백

| 내용 | 근거 |
|---|---|
| 소리가 만족스럽다는 평가 | 데모 플레이어 보고 R12 |
| 화면은 점점 격해지는데 소리는 잔잔하게 남는다는 의견 | 데모 플레이어 보고 R12 |
| 많은 천체가 한꺼번에 폭발할 때 긴 끊김이 있었다는 보고 | 데모 플레이어 보고 R12. 정식판 상태로 일반화하지 않음 |

동시 파괴 때 소리를 몇 번 재생하는지, 동시 재생 상한이 있는지는 공개 자료에서 찾지 못했다. 우리 게임에는 아직 소리가 없다.

## 4. 특수 효과와 연쇄 제한

### 개발자가 직접 설명한 동작

전기 효과는 연쇄 번개이며, 업그레이드로 연쇄 수·분기 확률·기본 피해를 강화할 수 있다. 높은 등급 천체의 효과 피해에는 추가 배율도 적용된다.[R3]

개발자는 **특수 효과가 있는 천체에는 다른 특수 효과가 피해를 주지 않는다**고 설명했다. 이유는 재등장 가능성과 결합한 사실상 무한 연쇄, 테스트에서 발생한 큰 렉, 플레이어가 특수 천체를 직접 파괴하게 하려는 의도였다.[R4]

### 이 규칙에서 읽을 수 있는 것

| 측면 | 분석 |
|---|---|
| 연쇄 종료 | 효과가 다음 특수 효과의 발동원을 파괴하지 못하게 하여 연쇄 경로를 끊는다 |
| 플레이어 역할 | 자동 효과만으로 특수 천체 전체가 소모되지 않고 직접 조준할 대상이 남는다 |
| 성능 | 무제한 연쇄를 처리 기술에 맡기기 전에 게임 규칙에서 제한한다 |
| 비용 | 특수 천체가 많을 때 효과에 반응하지 않는 대상도 많아진다. 시각적 설명이 필요하다 |

제한의 범위는 "동일 종류끼리만 면역"이 아니다. 개발자 답변은 **특수 효과가 있는 다른 물체 전반**을 대상으로 설명한다.[R4]

다음은 확인되지 않았다.

- 번개가 항상 최근접 대상을 고르는지
- 한 번의 번개가 같은 대상을 다시 맞힐 수 있는지
- 효과를 재귀 호출, 대기열 또는 다른 방식으로 처리하는지
- 재생성된 천체가 원래 특수 효과를 계승하는지

## 5. 천체의 생성과 파괴

### 5.1 파괴

| 내용 | 근거 |
|---|---|

**분석:** 원작의 파괴는 두 층으로 나뉜다.

```text

 - 보상 지급                  - 설정으로 끌 수 있음
                              - 후반에는 일부 생략
```

입자를 꺼도 게임이 진행되고 보상이 흡수 전에 지급되므로, 게임 결과가 연출의 완료를 기다리지 않는다. 우리 GAME_RULES 8·9절(`Gameplay Lifetime ≠ Presentation Lifetime`)과 같은 방향이다.

**분석:** 파괴 뒤 생성이 있으면 처리 순서가 결과를 바꾼다. 원작도 빈 화면 판정이 생성보다 먼저 돌아 문제가 보고됐다[E8]. 우리 GAME_RULES 13절은 Damage/Death(3) → Enemy Supply(7) → Battle End 판정(8) 순서로 이 문제를 피한다.

**분석:** 한 번에 여러 천체가 부서져도 천체마다 한 번씩 부서지고 한 번씩 보상한다. 여러 개를 한꺼번에 지우는 동작은 전투 끝(판 정리)에만 있을 수 있으며, 원작에서 그 모습은 확인하지 못했다.

## 6. 업그레이드 트리

### 6.1 노드 수와 선택의 폭은 다르다

공식 소개에는 정식판의 업그레이드가 200개 이상이라고 적혀 있다.[R2] 하지만 메인 모드의 선택 폭이 좁다는 의견에 개발자는 편안한 흐름과 만족스러운 성장 구간을 목표로 했다고 답했다. 다른 모드에는 비선형·격자형 트리가 있다고 설명했다.[R5]

**분석:** 노드 트리는 선택 경쟁을 제공할 수도 있고 콘텐츠를 순서대로 공개할 수도 있다. 노드 개수나 선의 모양만으로 전략적 선택이 많다고 판단하면 안 된다.

### 6.2 화면 관찰

플레이어 보고에 따르면 노드는 수치 강화뿐 아니라 새 천체(별)와 효과(초신성), 레이저 강화 묶음도 연다.[R10] 사용자 플레이 관찰로는 관통 레이저도 트리에서 해금한다(3.1).

사용자 확인으로 정리된 것: 노드는 한 단계이고, 사면 이웃이 드러나며, 자물쇠는 데모 잠금이다. 자세한 관찰과 우리 그래프 모델은 SKILL_TREE_PLAN 4절에 있다.

아직 확정하지 않은 것:

- 색이 기능 분류인지, 구역인지, 해금 단계인지
- 같은 아이콘이 별개 구매인지, 반복 강화인지

### 6.3 개발 책임으로 번역하면

아래 분리는 **우리 개발을 위한 분석**이며 원작 내부 설계에 대한 주장이 아니다. 지금 코드도 이 분리를 따른다(SKILL_TREE_PLAN 2절).

| 책임 | 필요한 정보 | 다른 책임과 구별되는 이유 |
|---|---|---|
| 노드 정의 | ID, 비용, 연결, 효과 | 구매 법칙을 설명한다 |
| 진행 상태 | 구매한 노드와 재화 | 플레이어별 결과다 |
| 효과 적용 | 어느 수치를 언제 어떻게 바꿀지 | 실제 다음 전투를 바꾼다 |
| 트리 화면 | 좌표, 연결선, 잠금·구매 상태, 입력 | 플레이어가 선택하고 이해하는 화면이다 |
| 저작 도구 | 노드·연결·좌표 편집, 오류 검사, 출력 | 개발자가 콘텐츠를 만드는 작업면이다 |

보이는 트리가 노드형이라는 이유만으로 원작이 특정 그래프 라이브러리나 전용 에디터를 썼다고 추정하지 않는다.

## 7. 모드와 버전의 구분

원작의 모든 모드를 하나의 규칙으로 합치지 않는다.

| 범위 | 확인 내용 | 분석상 주의 |
|---|---|---|
| 메인 모드 | 성장 속도와 편안한 흐름을 중시하는 트리 의도 | 다른 모드의 선택 규칙과 구분 [R5] |
| 데모 | itch.io의 플레이 버전, 별도 데모 업데이트 존재 | 오래된 댓글의 버그를 정식판 현재 상태로 일반화하지 않음 [R2] |
| Roguelike | 공식 패치에 Endless 성장 곡선과 성장 기록 변경이 있음 | 메인 모드의 성장·종료 조건으로 옮기지 않음 [R6] |
| Electric Moons | 행성 파괴 시 새 행성 확률 업그레이드 | 파괴 뒤 생성의 근거로만 쓰고 수치는 옮기지 않음 [E7] |
| Orb Breaker | 천체를 부수면 튕기는 구체가 추가로 천체를 파괴 | 원작의 모든 모드가 개체 수 증가를 억제한다고 볼 수 없음 [R6] |
| Just Keep Fishing | 커서를 따라가는 거북이 메커니즘 추가 | 기본 Breaker와 별도 조작·효과 구성 [R6] |

이 표는 전체 모드 목록이 아니라 조사에서 근거를 확인한 비교 범위다. 2026-09-03의 Patch 1.8.0 등 확인 가능한 공지 시점을 기록하며, 미래 변경까지 보장하지 않는다.[R6]

| 천체 종류·규모 변화 | 수량 외에도 성장감을 표현할 수 있다 | 원작이 후반 개체 수를 고정한다는 주장 |

| 노드 트리 | 구매·표시·저작을 별도 책임으로 분석할 수 있다 | 원작 전용 에디터나 데이터 형식의 단정 |

우리 성능 원칙은 이 분석에서 얻은 아이디어를 프로젝트 규칙으로 발전시킨 문서다. 원작이 그 원칙을 모두 구현했거나 일정 FPS를 보장한다는 증거가 아니다.
