# REFERENCE ANALYSIS (ENEMY) — 천체의 생성과 파괴

정리일: 2026-09-25

대상: Aarimous·Thornity의 **A Game About Feeding A Black Hole**

분석 중심: 메인 모드에서 천체(우리 게임의 Enemy)가 판에 **생기고 사라지는 형식**. 피해·HP·효과 계산은 다루지 않는다.

## 1. 이 문서를 읽는 방법

이 문서는 원작을 분석한 자료이며 우리 게임의 명세가 아니다. 구현해야 할 규칙은 [GAME_RULES_MVP](GAME_RULES_MVP.md), 시스템 책임은 [SYSTEM_CATALOG](SYSTEM_CATALOG.md)의 S03(Enemy 상태)·S05(사망 결과)·S08(공급·배치)·S09(전투 표현)를 따른다. 원작 전체의 분석은 [REFERENCE_ANALYSIS](REFERENCE_ANALYSIS.md)에 있다.

근거 표시는 [REFERENCE_ANALYSIS 1절](REFERENCE_ANALYSIS.md#1-이-문서를-읽는-방법)과 같다: 공식 / 개발자 답변 / 기존 플레이 관찰 / 사용자 플레이 관찰 / 플레이어 보고 / 분석 / 미확인.

- 원작의 "천체(object)"는 소행성·행성·별·달·혜성 등 파괴 대상 전체이며 우리 게임의 Enemy에 해당한다.
- 메인 모드가 아닌 모드(Zen, The Line, Electric Moons, Roguelike, Orb Breaker)의 근거는 모드를 함께 적는다. 모드 규칙을 메인 모드 규칙으로 옮기지 않는다.
- 개발자 답변이라도 사용자 플레이 관찰과 충돌하면 그 사실을 적고, 현재 동작의 근거로 쓰지 않는다.

## 2. 요약

| 결론 | 근거 수준 |
|---|---|
| 천체는 **하나씩 생기고 하나씩 사라진다.** "판의 천체를 한꺼번에 전부" 만들거나 지우는 경로는 공개 자료에서 찾지 못했다 | 분석 (3·4절의 자료 종합) |
| 파괴의 게임 결과(보상)는 **부서지는 순간** 지급되고, 조각이 블랙홀로 빨려 드는 것은 연출이다 | 사용자 플레이 관찰 (2026-09-25), 공식 설정 [E12] |
| 생성 계기는 여러 가지다: 전투 시작, 블랙홀 성장, 파괴 뒤 확률 생성, 달, 혜성 무리 | 공식·개발자 답변·기존 관찰·플레이어 보고 |
| 천체를 하나 만들 때마다 변형·크기·위치를 따로 굴린다. 다만 사용자 관찰로는 크기·돈은 색 등급이 정하고, 한 판에서 같은 색은 크기·돈이 같다 | 개발자 답변 [E6], 사용자 플레이 관찰 (2026-09-26) |
| 판의 천체 수는 유한하다. 모두 부수면 조기 종료 버튼이 나온다 | 공식 [E12] |

## 3. 파괴

### 3.1 확인한 내용

| 내용 | 근거 |
|---|---|
| 천체는 부서질 때 하나씩 사라진다. 플레이어는 "피해를 받아 죽는 것"과 "그냥 사라지는 것(despawn)"을 구분해서 보고한다 | 플레이어 보고 [E2], 메인 모드 에필로그 이후 |
| 부서진 천체의 조각은 블랙홀 주위를 돌다가 삼켜진다. 2025-09 데모에서 조각이 사라지지 않아 계속 돌면서 게임이 느려지고 성장 판정도 망가지는 버그가 보고됐고, 같은 글에 새 빌드로 해결됐다는 답글이 있다 | 플레이어 버그 보고 [E3], 데모 |
| 블랙홀로 흘러드는 입자는 설정에서 끌 수 있다(접근성·성능). 후반에는 입자 일부를 줄여서 그린다 | 공식 [E12 Day 1 Hotfixes], 개발자 답변 [E4] |
| **보상은 조각이 빨려 들기 전에 이미 지급된다.** 부서져 빨려 드는 과정을 거치지 않아도 마찬가지다 | 사용자 플레이 관찰 (2026-09-25) |
| 개발자는 "블랙홀 중력 안으로 밀려 들어간 천체는 부서져 빨려 들고 돈을 준다"고 답했다 | 개발자 답변 [E2], 2025-12-16. **사용자 플레이 관찰과 맞지 않아 현재 동작의 근거로 쓰지 않는다.** 사용자는 출시 초기의 버그들이 이후 수정된 것으로 본다 |
| 파괴가 생성을 부른다. 개발자는 천체에 재생성 확률이 있어서 특수 효과끼리 연쇄하면 사실상 끝나지 않는다고 설명했다(2025-12-17, Electric Moons 모드 추가 전). Electric Moons 모드에는 "행성이 파괴되면 새 행성이 생길 확률" 업그레이드가 있고, 1.4.1에서 최대 강화 시 100%가 되도록 바뀌었다 | 개발자 답변 [E5], 공식 [E12 Patch 1.4.1], 개발자 답변 [E7] |
| 판의 천체는 유한하다. 1.3에서 화면의 천체를 모두 부수는 도전과제가 추가됐고(메인 모드에서도 가능), 모두 부수면 오른쪽 아래에 조기 종료 버튼이 나온다 | 공식 [E12 Patch 1.3] |
| Electric Moons 모드에서 조기 종료 버튼이 파괴 뒤 생성보다 먼저 판정되어, 새로 생긴 천체가 있는데도 버튼이 나온다는 보고가 있다 | 플레이어 보고 [E8] |
| 일시정지 메뉴에 판 끝내기(End Session)가 있고, 누르면 남은 시간이 사실상 0이 된다 | 개발자 답변·플레이어 보고 [E9], [E2] |

### 3.2 해석

**분석:** 원작의 파괴는 두 층으로 나뉜다.

```text
부서짐 (게임 결과)          조각·입자 흡수 (연출)
 - 목록에서 빠짐              - 블랙홀 주위를 돌다 삼켜짐
 - 보상 지급                  - 설정으로 끌 수 있음
                              - 후반에는 일부 생략
```

입자를 꺼도 게임이 진행되고 보상이 흡수 전에 지급되므로, 게임 결과가 연출의 완료를 기다리지 않는다. 이는 우리 GAME_RULES 8·9절(`Gameplay Lifetime ≠ Presentation Lifetime`, 사망 순간 결과 확정)과 같은 방향이다. 원작의 내부 구현을 단정하지는 않는다.

**분석:** 파괴 뒤 생성이 있으면 처리 순서가 결과를 바꾼다.

```text
파괴 처리 → 파괴가 만든 생성 요청 → 생성 처리 → 빈 화면·종료 판정
```

원작도 빈 화면 판정이 생성보다 먼저 돌아 문제가 보고됐다[E8]. 우리 GAME_RULES 13절은 Damage/Death(3) → Enemy Supply(7) → Battle End 판정(8) 순서로 이 문제를 피한다.

**분석:** 한 번에 여러 천체가 부서져도 천체마다 한 번씩 부서지고 한 번씩 보상한다. 여러 개를 한꺼번에 지우는 동작은 전투 끝(판 정리)에만 있을 수 있으며, 원작에서 그 모습은 확인하지 못했다.

## 4. 생성

### 4.1 확인한 내용

| 계기·항목 | 내용 | 근거 |
|---|---|---|
| 전투 시작 | 판을 시작하면 천체가 배치된다 | 기존 플레이 관찰 ([REFERENCE_ANALYSIS 3.3](REFERENCE_ANALYSIS.md#33-성장과-공급)) |
| 블랙홀 성장 | 성장하면 소행성이 추가되고 시간이 늘어난다. 추가 수를 늘리는 업그레이드("spawn more asteroids")가 있다 | 기존 플레이 관찰, 플레이어 보고 [E11] |
| 파괴 뒤 | 재생성 확률, 행성 파괴 시 새 행성 확률 | 3.1절 [E5]·[E7]·[E12] |
| 달 | 행성을 부수기 시작하면 달이 생길 확률이 열린다. 달은 자기 행성 근처에 머문다 → 생성 위치의 기준이 HQ가 아니라 다른 천체인 경우가 있다 | 공식 [E12 Spoiler: Content In The Full Game] |
| 혜성 무리 | 혜성 무리는 혜성 여러 개를 한꺼번에 생성한다. 혜성과 혜성 무리의 생성 확률이 어떻게 관계되는지는 플레이어도 모른다 | 플레이어 보고 [E10] |
| 개체마다 무작위 | 천체를 하나 만들 때마다 변형(질량 업그레이드 확률에 따른 빨강/주황), 크기, 위치를 따로 정한다. 위치가 가까운 정도에 따라 부술 수 있는 양도 달라진다 | 개발자 답변 [E6], The Line 모드 토론 |
| 색 등급 | 소행성·행성·별은 각각 여섯 색(벽돌·주황·노랑·초록·파랑·보라)을 가진다. 한 종류 안에서 윤곽은 같고 색이 크기·HP·돈을 정한다. 한 판에서 같은 색은 돈이 정확히 같고, 색의 비율은 판마다 거의 같다. 종류별 질량 증가 옵션이 윗 색 비율과 그 종류의 HP·Gold 계수를 올린다. 황금은 소행성에만 붙는 특성이며 "황금 소행성 추가" 업그레이드로 열린다. 자세한 정리는 [BATTLE_COMPOSITION_PLAN 2.1](BATTLE_COMPOSITION_PLAN.md#21-사용자-플레이-관찰-2026-09-26) | 사용자 플레이 관찰 (2026-09-26). 크기에 관해서는 개발자 답변 [E6]과 다르며 사용자 관찰을 따른다 |
| 나타나는 방식 | 데모의 소행성은 날아 들어오지 않고 제자리에 그냥 나타난다 | 플레이어 제안 [E13], 데모 |
| Zen 모드 | 소행성이 크기 1~3 중 무작위로 생성된다 | 공식 [E12 Patch 1.2], Zen 모드 |

### 4.2 미확인

- 나타날 때 연출이 있는지 (데모의 "그냥 나타남" 보고 외)
- 성장 공급이 한 번에 모두 나오는지, 나뉘어 나오는지
- 재생성된 천체가 부서진 자리에서 나오는지, 다른 곳에서 나오는지
- 달이 행성 주위를 도는지, 근처에 놓이기만 하는지
- 동시에 존재할 수 있는 천체 수의 상한과, 상한에 닿았을 때의 처리
- 전투가 끝날 때 남은 천체를 화면에서 어떻게 치우는지

### 4.3 해석

**분석:** 원작의 생성은 다음 형식으로 읽을 수 있다.

```text
계기(시작·성장·파괴 뒤·달·혜성 무리) → 몇 개를 만들지 → 개체마다 변형·크기·위치 결정 → 판에 추가
```

계기마다 위치의 기준이 다를 수 있다(HQ 둘레 / 부모 천체 근처). 

**사용자 판단 (2026-09-25):** 시스템에서 생성은 특정 시점에 즉시 일어난다. 나타나는 모습은 연출일 뿐이며 생성 절차의 일부가 아니다.

## 5. 우리 적 시스템과 비교

2026-09-25 코드 기준. "다음 작업"은 같은 날 사용자가 정한 방향이다.

| 주제 | 원작 | 우리 현재 | 다음 작업 |
|---|---|---|---|
| 생성 계기 | 시작·성장·파괴 뒤·달·혜성 무리 | 전투 시작 공급 한 번 | 생성 요청을 쌓고 생성 절차로 처리. MVP 공급 계기는 시작·Growth Milestone뿐이다(GAME_RULES 12절). 파괴 뒤 생성·달·혜성 무리는 후속(F05) |
| 생성 처리 | 개체마다 무작위, 즉시 나타남 | 0초에 한꺼번에, 개체마다 위치 무작위 | 요청을 받은 시점에 즉시 생성. 나타나는 연출은 다루지 않음 |
| 파괴 입구 | 부서지는 순간 결과 확정 | `World.DealDamage` 하나. 게임에서 부르는 곳 없음 | 파괴 요청을 쌓고 적 정리 절차로 처리. 피해·HP 계산은 다루지 않음 |
| 파괴 뒤 | 조각·입자 흡수(연출), 재생성 확률 | 목록에서 즉시 빠지고 화면도 즉시 지움 | 파괴 연출은 넣지 않음. 재생성은 후속 |
| 한꺼번에 제거 | 찾지 못함 | 전투 종료 정리(처치 아님) | 그대로 둠 |
| 천체가 0이 됨 | 조기 종료 버튼 | 없음 | 이번 범위 밖 |
| 시험 방법 | — | 콘솔의 전투 시작·종료 | 생성·파괴 요청 목록을 버튼으로 두는 콘솔 창 |

## 6. 추가 관찰 목록

원작을 플레이하며 확인할 질문이다. 버전·모드·업그레이드 상태를 함께 기록한다.

| 확인할 질문 | 관찰 방법 | 관련 시스템 |
|---|---|---|
| 성장 공급은 한 번에 나오는가, 나뉘어 나오는가? | 성장 순간을 녹화해 새 천체가 나타나는 프레임 비교 | S08 |
| 재생성된 천체는 어디에 나오는가? | 재생성 노드 구매 후 행성 파괴 위치와 새 행성 위치 비교 | S08·F05 |
| 달은 행성 주위를 도는가? | 달이 붙은 행성을 여러 초 관찰 | S03·F05 |
| 전투가 끝날 때 남은 천체는 어떻게 사라지는가? | 시간 종료와 End Session 두 경우를 녹화 | S01·S09 |
| 여러 개가 동시에 부서질 때 보상 표시는 개별인가? | 한 공격으로 여러 개를 부수는 장면의 떠오르는 숫자 비교 | S05·S09 |
