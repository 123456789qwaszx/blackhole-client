## 1. 게임을 이렇게 읽는다

사용자 설명: 뱀파이어 서바이벌과 같은 구조에서 캐릭터와 액티브 스킬을 없애고, 레벨업 카드 3택을 노드 트리로 바꿨다. 스킬은 4종이고, 전기·폭발·처치 시 버프·처치 시 공격 주기 감소 버프로 연쇄를 만든다.

| 뱀파이어 서바이벌 | 이 게임 | 지금 레포 |
|---|---|---|
| 캐릭터 | 없음. 플레이어는 조준점만 움직인다 | `BattlePlayer.AimPoint` |
| 무기 (자동 공격) | 패시브 스킬 4종 | Breaker, 관통 레이저 |
| 액티브 스킬 | 없음 | 없음 |
| 레벨업 카드 3택 | 전투 밖에서 노드 트리의 노드를 산다 | 노드 그래프·구매 규칙·업그레이드 화면 |
| 패시브 아이템·진화의 시너지 | 천체 특성의 연쇄: 전기, 폭발, 처치 시 버프, 처치 시 공격 주기 감소 | 연쇄 번개, 폭발, 공격 주기 감소, 확정 치명타 |

- 전기·폭발·처치 버프는 **천체(적)의 사망 효과**다. 원작의 전기 천체(연쇄 번개), 초신성(폭발로 보임), 달(파괴하면 일정 시간 Breaker 강화), 혜성(커서 공격이 항상 치명타)과 같은 자리다 [원작]. 원작 플레이어도 전기가 플레이어가 아니라 소행성의 특성이라고 적었다 [원작 S7].
- 노드 구매는 **전투 밖**이다. 카드 3택을 대신하지만 전투 중에 고르지 않는다.

### "스킬 트리"가 아니라 "노드 트리"

원작 트리의 노드는 스킬 강화만이 아니다. 새 천체·효과 해금, 성장 공급 강화, 레이저 강화 묶음이 있다 [원작 R10]. 그래서 노드 트리를 **여러 시스템에 보정을 나눠 주는 독립 시스템**으로 두고, 스킬 시스템은 그 받는 쪽 중 하나로 둔다.

## 2. 세 덩어리와 하나의 접점

```text
[편집]    노드 도구 (메뉴 BlackHole > Node Tree)
            │ 저장
            ▼
[데이터]  노드 목록 에셋 (NodeCatalog): 노드 ID · 가격 · 시작 노드 · 격자 칸 · 연결선 · 업그레이드 목록

[전투 밖] 노드 트리 (NodeGraph, NodePurchase)  ◀── 노드 ID 구매 요청 ───  업그레이드 화면
            │                                   ─── 노드 상태 · 구매 결과 ──▶
            │ 방장의 산 노드
            ▼
          업그레이드 표 (UpgradeTable) ── 수치 이름 → (기본값 + Σ더하기) × (1 + Σ비율) × Π곱하기
            │
[경계]    판 조립 ── 각 시스템이 자기 수치 이름으로 최종 값을 가져간다
            │           Breaker: breaker.*  ·  적: enemy.<종류>.*  ·  블랙홀: hq.*
            ▼
[전투 안] 스킬  ◀── 처치 버프 (시간 제한) ──  사망 효과 (연쇄 번개 · 폭발 · 처치 버프)
```

노드 트리와 스킬 시스템을 잇는 것은 **업그레이드 표 하나**다. 의존 방향은 한쪽뿐이다.

```text
노드 ──(수치 이름)──▶ 업그레이드 표 ◀──(자기 수치 이름, 기본값)── 스킬·적·블랙홀
스킬·적·블랙홀 ──── ✕ ────▶ 노드 (노드가 있는지 모른다)
업그레이드 표 ──── ✕ ────▶ 수치의 뜻 (이름을 해석하지 않는다)
```

### 2.1 소유와 모르는 것

| 시스템 | 소유 | 모르는 것 |
|---|---|---|
| 스킬 | 종류별 정의·기본 수치·**수치 이름**, 실행 상태, 한계, 처치 버프 적용 | 노드, 가격, 연결, 좌표 |
| 사망 효과 | 효과 정의, 대기열, 끝나는 규칙, 버프 발생 | 노드, 구매 |
| 노드 트리 | 노드 ID·가격·업그레이드 목록, 연결선, 드러남·구매 판정 | 수치의 뜻, 스킬이 어떻게 도는지 |
| 업그레이드 표 | 수치별 합성 | 수치의 뜻, 업그레이드가 어디서 왔는지 |
| 업그레이드 화면 | 격자 칸 배치, 상태 색, 확대·이동 | 구매 조건 계산(노드 트리에 묻는다) |
| 노드 도구 | 편집 화면, 즉시 검사, 구매 미리보기, 저장 | 전투 실행 |

### 2.2 분리를 확인하는 기준

1. 스킬 종류를 하나 더해도 노드 트리·업그레이드 코드를 고치지 않는다. 새 종류가 수치 이름을 공개하면 노드가 그 이름을 쓸 수 있다.
2. 노드를 더하거나 선을 바꿔도 스킬 코드를 고치지 않는다.
3. 노드 목록 안의 순서나 업그레이드를 받은 순서를 바꿔도 결과가 같다 — 계약 `Upgrade.OrderDoesNotChangeTheValue`.
4. 업그레이드 화면은 노드 ID, 구매 결과, 노드 상태만으로 동작한다.

1·2는 코드 리뷰 기준이다. 3은 계약으로 고정했다.

## 3. 스킬 시스템

### 3.1 공통

- 스킬은 참가자마다, 판마다 따로 실행 상태를 가진다. 판 안의 참가자(`BattlePlayer`)는 조준점과 스킬 목록을 가진다. 전투 밖 진행 상태(`PlayerState`)와 다르고, 캐릭터도 아니다.
- 호스트가 프레임마다 로컬 참가자의 조준점을 넣는다(`GameSession.SetAimPoint`). 마우스는 지금 쓰는 출처일 뿐이다(`Unity/Skills/AimInput`).
- **모든 참가자가 콘텐츠의 스킬을 전부 받는다.** 레이저를 노드로 여는 것은 아직 없다(9절).
- 스킬은 `World.Step`의 2. Passive Attack 자리에서 참가자 순서로, 참가자 안에서는 콘텐츠의 스킬 순서로 돈다.
- 피해는 `World.DealDamage` 하나로 들어간다. 스킬은 대상을 먼저 모두 모은 뒤 피해를 준다(죽은 적이 목록에서 바로 빠지기 때문이다).
- 모든 스킬의 공통 수치는 두지 않는다. 같은 "피해"라도 종류마다 따로 선언한다. 두 스킬을 묶는 인터페이스도 없다.
- 한 Step 동안 주기가 여러 번 차면 그만큼 공격한다. 같은 Step 안의 공격은 같은 조준점과 같은 적 위치를 본다. 프레임당 한 Step이다.
- 켜기·끄기(`SetEnabled`)는 개발용 스킬 콘솔만 부른다. 끄면 돌던 주기와 예고를 버리고, 다시 켜면 켠 뒤 첫 Step부터 처음처럼 돈다. 게임 규칙으로 끄는 일은 없다.
- 표현은 기록(순번 있는 Tick·예고·발사·번개·폭발)을 읽기만 한다. 같은 기록을 두 번 그리지 않는다.

### 3.2 Breaker와 관통 레이저

| | Breaker | 관통 레이저 |
|---|---|---|
| 공격 | 주기마다 조준점 중심 원 안의 살아 있는 적 전부 | 주기마다 경계 원 위의 무작위 지점에서 조준점을 향해 예고하고, 예고가 끝나면 그 직선 위(굵기 절반 안)의 적 전부를 관통 |
| 첫 공격 | 판의 첫 Step (GAME_RULES 6절) | 첫 예고가 판의 첫 Step [임시] |
| 조준점이 없을 때 | 빈 Tick. 주기는 소비된다 | 그 주기는 예고 없이 지나간다. 조준점이 경계 밖이어도 같다 [샌드박스 선택] |
| 경로 | — | 예고를 시작할 때 조준점을 저장한다. 이후 조준점이 움직여도 그 발사의 경로는 같다 [원작 관찰] |
| 치명타 | 맞을 적이 있는 Tick마다 한 번 판정, 맞은 적 모두 같은 결과. 맞을 적이 없으면 난수를 뽑지 않는다 [샌드박스 선택]. 치명타면 피해 × `CritMultiplier` | 없음 |
| 난수 | 치명타 전용 스트림 | 시작점 전용 스트림. 출현 배치가 뽑는 횟수에 흔들리지 않는다 |
| 처치 버프 | 받는다 (3.4) | 받지 않는다 |
| 노드 수치 | `breaker.damage`, `breaker.speed`, `breaker.radius`, `breaker.crit-chance` (5.2) | 없음 |
| 샘플 [임시] | 피해 2, 주기 1초, 반지름 1.5, 치명타 확률 0, 배율 2 | 피해 3, 주기 4초, 굵기 0.5, 예고 0.4초, 경계 반지름 11 |

- 치명타는 **Breaker의 수치**다. 원작의 치명타는 Breaker의 강화 축이다(REFERENCE_ANALYSIS 3.1) [사용자 확정]. 샌드박스의 "치명타·공격 간격은 플레이어 공통 수치"는 따르지 않았다.
- 경계 반지름은 공간 값이라 노드가 바꾸는 수치가 아니다.
- 수치는 스킬 설정 에셋(`Data/SkillSetup.asset`)에 있다. 칸이 없으면 그 스킬 없이 판이 돌고, 잘못된 수치는 로드 때 경로와 함께 보고한다.

### 3.3 사망 효과

사망 효과는 적 종류에 붙는 **특성**이다. 종류가 아니다(전기 소행성은 연쇄 번개를 가진 적 종류다).

| 효과 | 샘플 종류 | 하는 일 | 샘플 [임시] |
|---|---|---|---|
| 연쇄 번개 | 전기 소행성 | 죽은 자리에서 가장 가까운 적으로 번개가 옮겨 가며 피해. 한 번 옮기는 거리 ≤ 반경, 횟수 ≤ 최대 수, 한 번 맞힌 적은 다시 맞히지 않음. 거리가 같으면 목록 순서 | 피해 5, 반경 2.5, 최대 3 |
| 폭발 | 초신성 | 죽은 자리 중심 반경 안의 적 전부에게 한 번 피해. 원작 초신성의 피해 공식은 미확인 | 피해 7, 반경 2.5 |
| 공격 주기 감소 | 달 | 일정 시간 Breaker 주기 × 배율 (3.4) | 5초, 0.5배 |
| 확정 치명타 | 혜성 | 일정 시간 Breaker의 Tick이 모두 치명타 (3.4) | 5초 |

- **사망 효과를 가진 적은 사망 효과의 피해를 받지 않는다**(GAME_RULES 10절, 원작 개발자 설명 R4). 그래서 효과로 생긴 사망은 새 효과를 부르지 않고, 대기열은 한 번 훑으면 끝난다.
- 대기열: 효과를 가진 적이 **피해로** 처음 죽는 순간 효과·죽은 자리·마지막 피해의 출처를 넣는다. Step 4에서 사망 순서대로 처리한다. 효과 피해도 `World.DealDamage`로 준다.
- 파괴 요청으로 죽은 적(피해 출처가 없는 사망)은 효과를 내지 않는다 [제안]. 파괴 요청은 개발용 적 명령 콘솔만 쓴다.
- 효과로 죽은 적도 같은 Step의 사망·처치 수에 든다. 판이 끝나면 처리되지 않은 효과는 버린다.
- 효과 피해의 출처는 기록일 뿐 귀속 규칙이 아니다(`Damage.Source`).

### 3.4 처치 버프

- 공격 주기 감소·확정 치명타 모두 **Breaker에만** 붙는다. 원작에서 달은 Breaker를 강화하고(R7·R9), 혜성은 커서 공격을 항상 치명타로 만든다(R8) [사용자 확정]. 달의 강화가 "공격 주기 감소"라는 것은 사용자 설명에 맞춘 해석이다 [분석].
- **판 안의 모든 참가자의 Breaker에 붙는다.** 누가 죽였는지는 보지 않는다. 스탯처럼 판 전체가 공유한다 [사용자, 2026-09-27] — 계약 `Buff.IsSharedRegardlessOfWhoKilled`.
- 사망 효과는 공격 뒤(Step 4)에 처리되므로, 버프는 그 처치가 난 Step의 공격에 들지 않고 **다음 Step부터** 적용된다. 한 Step의 공격은 Step을 시작할 때의 버프로 하고, 버프 시간은 공격 뒤에 준다.
- 공격 주기 감소: 돌던 주기의 진행률은 그대로 두고 남은 부분만 빨리 찬다.
- 확정 치명타: 배율은 Breaker의 `CritMultiplier`다. 버프가 배율을 따로 갖지 않는다.
- 같은 종류를 다시 받으면 남은 시간은 긴 쪽, 주기 배율은 강한 쪽(작은 값)을 남기고 곱으로 쌓지 않는다 [샌드박스 선택].
- 버프 시간은 스킬이 꺼져 있어도 흐른다. 다음 판으로 넘어가지 않는다.

## 4. 노드 그래프

### 4.1 원작에서 확인한 것

| 관찰 | 근거 |
|---|---|
| 본편 노드는 한 단계다. 사면 끝이고 여러 레벨이 없다 | 플레이어 보고 [S2] |
| 노드를 사야 그 너머가 드러난다. 한때 살 수 있는 노드가 적다 | 플레이어 보고 [S2] |
| 트리 화면은 휠로 확대, 끌어서 이동 | 플레이어 보고 [S2] |
| 강화 설명은 `Breaker Speed Currently: 175%`처럼 현재 합계를 보여 준다. 플레이어는 `+10%`처럼 이번 노드의 몫을 보고 싶어 했다 | 플레이어 보고 [S2] |
| 시작 노드 주변에 5회씩 사는 노드, 에필로그 노드는 1/10부터 10단계 | 플레이어 보고 [S1], 개발자 답변 [S5] |
| 자물쇠 노드는 데모 모드에서 잠긴 노드다. 개발자는 이를 없앨 수 있다고 했다 | 개발자 답변 [S4] |
| 밸런스 업데이트로 노드를 추가·삭제했고, 기존 진행을 모두 돌려주지 못했다 | 개발자 답변 [R10] |
| 가격이 뒤로 갈수록 커지고 T(조) 단위까지 표시된다 | 플레이어 보고 [R5], 개발자 답변 [S3] |
| 노드 수를 크게 늘리기 위한 업데이트, 정식판 업그레이드 200개 이상 | 개발자 공지 [S6], 공식 [R2] |
| 트리가 거의 일직선이라는 평 | 플레이어 보고 [R5, S7] |

사용자가 준 스크린샷에서 읽은 것 [분석]: 중앙의 육각 노드가 시작점이고 색마다 가지가 뻗는다. 노드는 격자 칸에 놓이고 선은 수평·수직이다. 2×2, 3×3, 십자 모양 묶음이 많고, 묶음 안에서는 이웃끼리 이어져 순환이 생긴다. 회색 사각 노드의 자물쇠는 데모 잠금이다(게임 규칙의 잠금이 아니다) [사용자 확인].

### 4.2 그래프 모델

```text
노드       = ID, 가격, 시작 노드인가, 격자 칸 (X, Y), 연결선, 업그레이드 목록
연결선     = 두 노드 ID (방향 없음). 양쪽에 적어도 한 선이다
시작 노드  = 산 이웃이 없어도 드러나는 노드 (샘플: start, asteroid-mass-1)

드러남     = 시작 노드이거나, 산 노드와 선으로 이어져 있다
살 수 있음 = 드러남 + 전투 중 아님 + 산 적 없음 + Gold ≥ 가격
```

- **선이 보이는 모양이자 구매 조건이다.** 선행은 "이웃 중 하나"(OR)다. 원작의 "사야 너머가 드러난다"와 격자 묶음의 순환 연결에서 읽었다 [분석, 사용자 확인].
- 순환을 허용한다. 대신 "모든 노드가 시작 노드에서 닿는다"를 로드 때 검사한다.
- AND 선행과 구역 잠금은 원작 근거가 없어 만들지 않았다.
- **격자 칸은 표시용이다.** 이웃한 칸이라고 선이 생기지 않는다. 선은 저작자가 그은 것만이다 [사용자: 칸 이웃을 자동으로 잇는 방식은 답답했다]. 이웃끼리 한 번에 잇고 싶으면 노드 도구의 "이웃끼리 잇기" 명령을 그 순간 쓴다.
- 노드 상태는 네 가지다(`NodeState`): 숨김 · 드러남(살 수 없음) · 살 수 있음 · 산 것.
- 구매 결과(`PurchaseResult`): 샀음 · 없는 노드 · 이미 가짐 · 숨김 · 전투 중 · Gold 부족. 실패한 구매는 아무것도 바꾸지 않는다.
- 환불은 없다(원작에 없다). 여러 번 사는 노드도 없다.
- 노드 ID는 저장 키다. 산 노드가 노드 목록에 없으면 업그레이드 표를 만들 수 없다.

## 5. 업그레이드

### 5.1 합성 규칙

노드 하나는 업그레이드 목록을 가진다. 업그레이드 하나는 **수치 이름 + 연산 + 값**이다.

| 연산 | 뜻 | 쌓이는 방식 |
|---|---|---|
| 더하기 (`Add`) | 기본값에 더한다. 예: 질량 단계 +1 | 합 |
| 비율 (`Percent`) | 비율을 더한다. 0.25는 +25% | 합 (원작의 "Currently: 175%") |
| 곱하기 (`Multiply`) | 곱한다 | 곱 (원작의 황금 자릿수: ×10 두 번이면 ×100) |

```text
최종 값 = (기본값 + Σ더하기) × (1 + Σ비율) × Π곱하기
```

- 받은 순서는 결과를 바꾸지 않는다. 같은 업그레이드 묶음이면 끝자리까지 같은 값이다.
- 업그레이드가 없는 수치는 기본값 그대로다. **기본값은 가져가는 시스템이 준다.**
- 한계(0 이상, 1 이하, 정수 등)는 가져가는 시스템이 최종 값에 건다. 업그레이드 표는 값이 유한한지만 본다.
- 판 조립 때 **방장의 산 노드로 표를 한 번** 만든다. 판이 끝날 때까지 같다(전투 중에는 살 수 없다). 노드 트리 없이 조립하면 빈 표다.

### 5.2 수치 이름

| 이름 | 가져가는 시스템 | 기본값 | 한계 |
|---|---|---|---|
| `breaker.damage` | Breaker | 콘텐츠의 피해 | > 0 |
| `breaker.speed` | Breaker | 1. 주기 = 기본 주기 ÷ 공격 속도 [임시] | > 0 |
| `breaker.radius` | Breaker | 콘텐츠의 반지름 | > 0 |
| `breaker.crit-chance` | Breaker | 콘텐츠의 확률 | ≥ 0, 1에서 멈춤 |
| `hq.growth-time` | 블랙홀 | 0 | ≥ 0. Level업마다 그 판의 제한 시간에 더한다 |
| `enemy.<종류>.*` | 적 | — | [BATTLE_COMPOSITION_PLAN 3.3](BATTLE_COMPOSITION_PLAN.md#33-판-조립--판-구성을-정한다) |

- 레이저를 보정하는 노드는 없어서 레이저 수치 이름은 두지 않았다. 치명타 배율을 바꾸는 노드도 없다.
- 노드를 모두 산 조합도 판을 조립할 수 있는지는 게임 시작 때 `UpgradeContentCheck`가 본다(Breaker 한계, 음수 성장 시간, 적 쪽 검사). 실패하면 게임이 시작하지 않는다.

### 5.3 샘플 노드 [임시]

노드 목록(`Data/NodeCatalog.asset`)에 56개가 있다. `enemy.*` 수치를 쓰는 노드 47개(성장 공급 포함)는 [BATTLE_COMPOSITION_PLAN 4절](BATTLE_COMPOSITION_PLAN.md#4-샘플-콘텐츠-임시)에 있다. 나머지 9개:

| 노드 | 가격 | 수치 | 값 |
|---|---|---|---|
| start (시작 노드) | 10 | `breaker.damage` | 더하기 1 |
| damage-1 | 25 | `breaker.damage` | 더하기 1 |
| speed-1 · speed-2 | 25 · 60 | `breaker.speed` | 비율 0.25 |
| square-a · square-b | 50 · 50 | `breaker.radius` | 비율 0.1 |
| square-c · square-d | 50 · 120 | `breaker.crit-chance` | 더하기 0.05 |
| growth-time | 20 | `hq.growth-time` | 더하기 3초 [사용자] |

- 적 종류 노드의 격자 칸은 Breaker 노드 왼쪽에 계열별로 둔 임시 배치다.
- 노드 표시 이름·설명·아이콘 칸은 아직 없다. 화면은 ID와 가격을 보인다.

## 6. 업그레이드 화면

| 보이는 것 | 알리는 것 |
|---|---|
| Gold, 산 노드 수 / 전체, 블랙홀 Lv·%·이정표 n / 전체, 노드 트리 | 노드 ID 클릭, Start battle |

- **배치는 노드 도구와 같은 좌표다.** 칸 (X, Y)의 노드는 (X × 칸 크기, Y × 칸 크기)에 놓인다. X는 오른쪽, Y는 위쪽이다. 선은 그래프(`NodeGraph.Links`)에서 읽는다.
- 상태 색: 숨김은 그리지 않는다 [원작] · 드러남(Gold 부족) 회색 · 살 수 있음 노랑 · 산 것 초록. 선은 양 끝이 모두 보일 때만 그리고, 양 끝을 모두 샀으면 밝게 칠한다.
- 노드 클릭: 살 수 있으면 바로 산다. 빈 곳이나 노드 위를 끌면 이동이고, 끌었으면 떼어도 사지 않는다. 휠은 커서 위치 중심으로 확대·축소(0.3 ~ 2.5배). 열 때 노드 전체의 범위가 보이게 맞춘다.
- 화면은 규칙을 모른다. 노드마다 칸·가격·상태와 선 목록을 받아 그리고, 눌린 노드 ID를 알린다. 가격·구매 가능 여부는 `NodePurchase`가 가진다.
- 트리 보기(`NodeTreeView`)는 업그레이드 화면을 호스트로 두는 페이지다. `ScreenFlow`가 업그레이드 화면을 연 뒤 트리를 짓고 노드 클릭을 연결한다. 화면 갱신은 `ScreenFlow.RefreshUpgrade` 한 곳이 계산한다(화면 진입·구매·개발용 업그레이드 콘솔이 부른다).
- 글자는 TMP 기본 글꼴이라 영문·숫자다.

## 7. 노드 도구 (메뉴 BlackHole > Node Tree)

노드 목록 에셋을 격자 위에서 고친다. Editor 어셈블리에 있고, 편집 규칙은 엔진 없는 `Authoring` 어셈블리(`NodeTreeAuthoring`)에 있다. Core는 Unity 없이 컴파일되는 상태를 유지한다.

- **편집**: 칸에 노드를 놓고 옮기고 지운다(한 칸에 노드 하나). 놓기·옮기기는 선을 건드리지 않는다. 잇기는 Shift+끌기, 끊기는 선을 눌러 Delete. 여러 노드를 고르면 명령이 나온다: 둘 잇기, 이웃끼리 잇기, 선택끼리 끊기, 선 모두 지우기.
- **검사**: 고칠 때마다 게임과 같은 로더(`NodeTreeLoader`)로 불러 보고, 도구 검사(겹친 칸, 값을 줄이는 곱하기)를 더한다. 진단을 누르면 그 노드로 간다.
- **구매 미리보기**: 게임과 같은 규칙으로 노드를 사 보며 네 가지 상태와 업그레이드 합계를 본다. Gold는 무한이다. 산 노드를 다시 누르면 미리보기에서만 되돌린다.
- 고친 내용은 Undo로 되돌릴 수 있고, 저장 버튼이나 프로젝트 저장으로 에셋에 쓴다.
- 캔버스는 UI Toolkit으로 직접 그린다. GraphView는 포트와 방향 있는 선을 전제로 해서 격자 칸·무방향 선에 맞지 않았다. 쓸 만한 외부 트리·스탯 라이브러리도 찾지 못했다(PoE 트리 = 규칙의 계보, Kryzarel 스탯 = 합성 공식의 계보로만 참고).
