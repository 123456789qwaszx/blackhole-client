# 작업 인계 — M7 완료 후

갱신: 2026-09-24 · M0~M7 완료. M8은 착수 조건 확인 전이다.

## 읽는 순서

[GAME_RULES](../GAME_RULES.md) → [레퍼런스 분석](../REFERENCE_ANALYSIS.md) → [PLAN](PLAN.md) → [RULES_ALIGNMENT](RULES_ALIGNMENT.md) → [M8](M8-review.md). M7 결과는 [M7](M7-death-effects.md)의 "결과" 절에 있다.

## 기존 인계에서 바뀐 점

- 첨부된 M3 인계서의 M2/M3 미push 기록은 현재와 다르다. 두 커밋 모두 원격 dev에서 확인했다.
- D1(HQ 성장 제외), D4(Player EXP만 누적)는 최신 규칙에 따라 대체됐다.
- M4 보상은 Player Gold와 HQ EXP다. Player Level은 만들지 않는다.
- 생성 시 구매 보정 확정은 더 이상 임시 규칙이 아니다.
- 구매 상태는 전투 사이 유지해야 한다. 새 World/Skill 조립과 모든 진행 초기화를 혼동하지 않는다.
- 사망 효과는 사망 효과를 가진 적에게 피해를 주지 않는다(레퍼런스와 같다). 효과끼리의 연쇄는 없다.
- 원본 첨부 HANDOFF는 과거 작업자의 기록이며 최신 지시로 덮어쓰지 않는다.

## 현재 코드

Core/Sample/Unity/Tests 경계, Player별 조준점·스킬, HQ 기준점, Orbit 교체 경계가 있다.
PlayerState는 전투 사이에 유지되는 진행 데이터(Gold, 산 노드 ID)이고, Player는 전투마다 새로 만든다. HQ는 위치·누적 EXP·Level을 가지며 전투마다 초기화된다. 사망은 즉시 확정되고 Gold·HQ EXP·사망 기록을 한 번 남긴 뒤 목록에서 빠진다. 화면은 사망 기록으로 흡수 연출을 한다.
적은 판 시작 배치와 성장 공급으로만 나온다. 성장하면 Level마다 적이 추가되고 판 시간이 늘어난다. 전투가 끝나면 구매 화면에서 노드를 사고 다음 전투로 간다. 노드 저작 툴은 별도 작업이다.
전기 적이 죽으면 연쇄 번개가 가까운 적으로 튄다. 효과는 대기열로 처리하고, 화면은 적중 기록으로 번개를 그린다.
World.Step은 이동 → Skill(피해·사망·보상·Level) → 사망 효과 → 성장 진행 → 공급된 적 생성이고, 종료 판정은 그 뒤다. SessionLauncher는 Stop → View.Reset → 새 조립이다.
이 상태를 완료된 최신 게임으로 해석하지 않는다.

## 다음 작업

M8의 범위와 "착수 전에 정할 것"을 먼저 검토한다. M8은 새 게임 규칙을 추가하지 않는다. 변화 실험, v2 예제집, [임시] 목록 정리, 팀 분배 자료가 대상이다. 결정 전에는 구현하지 않는다.

## 작업 방식과 검증

- 계획 검토 → 구현 → CoreSmoke/가능한 분리 빌드·핵심 변이 검사 → 사용자 Unity 플레이 확인 → 결과/PLAN 갱신 → 의미 있는 커밋 1개.
- 다음 마일스톤은 사용자 확인 후 진행한다.
- 검증 기록: M7 기준 CoreSmoke 63개 통과, 분리 빌드 경고 0·오류 0. M7은 사용자가 Unity 플레이를 확인했다.
- Windows 로컬 경로와 열려 있는 Unity 상태는 과거 환경이다. 현재 실행 환경을 확인한다.
- 커밋의 기여자는 실제 작성자로 표기한다. 이전 에이전트 이름을 관례적으로 복사하지 않는다.
