# 팀 분배 자료 — 후보 시스템 표

갱신: 2026-09-24 · 기준: Reference v2 M0~M7과 M8 변화 실험

팀 설계와 티켓 분배의 출발 자료다. 시스템 후보는 [v2 예제집](SYSTEM_CATALOG.md)의 후보와 같다. 우리 게임의 확정 구조가 아니다.

- 담당자와 일정은 배정하지 않는다.
- 규모는 시간이 아니라 상대 규모(S/M/L)다. 근거는 Reference의 코드 양, 계약 수, 접점 수, 남은 미정 규칙이다. 이 Reference의 구현 기록은 팀 속도를 대표하지 못하므로 시간 환산은 팀이 한다.
- 인수 기준은 Reference에서 계약으로 확인한 것이다. 기획이 바뀌면 함께 바뀐다.

## 1. 목적·소유 상태·입출력

| 후보 | 목적 | 소유 상태 | 입력 | 출력 |
|---|---|---|---|---|
| 전투 세션 | 한 판의 수명과 시간 | 실행/정지/종료, 결과, 경과 시간, 판 제한 시간 | 프레임 시간, 정지·종료 요청, 시간 연장 | World 단계 호출, 종료 결과, 전투 잠금 해제 |
| 진행 상태와 전투 조립 | 전투를 넘는 상태를 지키고 새 전투를 만든다 | PlayerState(Gold, 산 노드 ID, 전투 잠금) | 콘텐츠, 진행 상태 | 새 전투(World, Player, Skill, 출현·공급·성장 설정) |
| 콘텐츠 정의·검증 | 데이터를 안전하게 공급한다 | 공유 정의(바뀌지 않음) | 저작 데이터 | 공유 정의 또는 경로별 진단 목록 |
| HQ 성장 | 블랙홀 성장 진행도 | HQ 위치, EXP, Level | 처치 EXP | Level, 다음 임계값 |
| 성장 진행과 공급 | 성장이 판을 바꾼다 | 공급 대기 목록 | 새 Level, 성장 노드, 구매한 공급량 보정 | 공급 요청, 시간 연장 |
| 출현 | 요청받은 적을 만든다 | 출현 순번 | 공급 요청, 구매 보정 | 실행 수치·보상이 확정된 적 |
| 적과 행동 | 적의 상태와 움직임 | 적별 위치, HP, 생존, 실행 수치·보상, 마지막 피해 출처 | 단계 시간, HQ 위치, 피해 | 다음 위치, 최초 사망 여부 |
| Passive Skill | 자동 공격 | Skill별 타이머, 실행 수치, 틱 수 | 기준점(조준점), 적 목록 | 피해 요청 |
| 피해·사망·보상 | 처치를 한 번 확정한다 | 사망 기록(한 Advance) | 피해 요청 | Gold(Player), HQ EXP, 사망 기록, 목록 제거, 효과 대기 |
| 사망 효과 | 죽음이 부르는 게임 효과 | 효과 대기열, 적중 기록(한 Advance) | 사망한 적의 효과, 사망 위치, 출처 | 피해 요청(같은 사망 절차), 적중 기록 |
| 업그레이드 | 전투 밖 구매와 효과 적용 | 노드 정의(콘텐츠) | 구매 요청, PlayerState | 구매 결과, 전투별 보정(Skill, 적, 보상, 공급) |
| 표현과 호스트 | 규칙을 화면·입력·전환에 연결한다 | View, 연출 진행, 마지막으로 소비한 기록 순번 | 마우스·키, World 읽기 | 조준점·요청, 화면, 구매 화면 |

## 2. 선행 작업·독립 검증·인수 기준

| 후보 | 선행 작업 | 독립 검증 방법 | 인수 기준(Reference 계약) |
|---|---|---|---|
| 전투 세션 | 없음. World 단계 순서의 합의 | 테스트 콘텐츠로 긴 프레임·정지·종료를 진행 | 제한 시간을 넘어 진행하지 않음, 결과 1회, 정지 중 시간 정지, 재시작은 새 조립, 연장이 그 단계의 판정에 들어감 |
| 진행 상태와 전투 조립 | 콘텐츠, 세션 | 진행 상태 두 개와 전투 두 번으로 유지·초기화 확인 | 다음 전투에 Gold·구매 유지, 실행 상태는 새로, 새 진행은 비어 있음, 전투 중 구매 불가, 없는 노드는 조립 오류 |
| 콘텐츠 정의·검증 | 데이터 형식 합의(노드 저작 툴과 공유) | 잘못된 데이터를 넣어 진단 경로 확인 | 오류를 경로와 함께 모두 보고, 오류가 있으면 정의 없음 |
| HQ 성장 | 사망·보상(EXP) | EXP를 임계값 전·같음·후로 넣음 | 임계값에서 Level 상승, 한 번에 여러 Level |
| 성장 진행과 공급 | HQ 성장, 출현, 세션(시간) | 테스트 콘텐츠의 성장 노드로 공급·연장 확인 | Level마다 효과 1회, 공급된 적은 다음 단계부터, 긴 프레임과 짧은 프레임의 결과가 같음, 판끼리 독립 |
| 출현 | 콘텐츠, 적과 행동 | 공급 요청만 넣고 위치·수치 확인 | HQ 기준 위치, 요청 순서대로 생성, 출현 때 수치 확정, 기본 정의 불변 |
| 적과 행동 | 콘텐츠 | 행동 대역을 꽂아 적 본체와 분리 확인 | HQ 둘레 공전, HQ 위치를 따름, 행동 교체 가능, 판끼리 적 공유 없음 |
| Passive Skill | 적과 행동, 진행 상태(Player) | 조준점과 적 배치를 정해 틱별 피해 확인 | 첫 틱 0초, 주기대로 틱, 원 안 전부·밖은 없음, 빈 틱, 긴 프레임의 틱 수, Player별 조준점·Skill |
| 피해·사망·보상 | 적과 행동, Passive Skill | 한 적에 여러 피해를 같은 단계에 줌 | 보상 1회, 사망 기록 유실 없음, 전투 정리에는 보상 없음, 다인 보상은 조립 거부 |
| 사망 효과 | 피해·사망·보상 | 원 위 배치로 번개의 대상 순서 확인 | 가까운 순서·최대 수, 효과 가진 적 제외, 효과 처치도 보상 1회, 성장보다 먼저 처리, 기록 유실 없음 |
| 업그레이드 | 진행 상태, 콘텐츠, 각 적용 대상(Skill·출현·공급) | 구매 → 다음 전투 → 실제 수치 변화 | 선행·Gold 판정, 실패는 상태 불변, 대상 Skill만 변화, 다인 공유 구매 거부 |
| 표현과 호스트 | 각 시스템의 읽기 전용 상태와 기록 | 사람 플레이 확인(PlayMode 테스트 없음) | 범위 원 = 실제 반경, 모든 처치에 연출, 전투 전환 후 화면 잔여 없음 |

## 3. 공동 수정 지점

한 사람이 한 시스템을 맡아도 아래 파일은 여러 사람이 함께 고친다. 마일스톤 커밋 7개(M1~M7) 중 몇 번 바뀌었는지를 적었다.

| 지점 | 함께 고치는 후보 | 이유 | 바뀐 횟수 |
|---|---|---|---|
| World 단계(`World.cs`) | Skill, 사망, 사망 효과, 성장, 공급 | 한 단계 안의 순서가 결과를 바꾼다. 순서는 계약 4개가 지킨다 | 7 |
| 콘텐츠 데이터·로더(`ContentData.cs`, `ContentLoader.cs`) | 모든 후보 | 새 정의 종류마다 칸과 해석이 늘어난다 | 7 |
| 샘플 콘텐츠(`SampleContent.cs`) | 모든 후보 | 실행 확인용 값 | 7 |
| 전투 조립(`SessionAssembler.cs`) | 진행 상태, Skill, 출현, 공급, 성장, 업그레이드 | 실행 값의 보정과 정책 검사가 모인다 | 6 |
| 화면·HUD(`WorldView.cs`, `Hud.cs`, `SamplePresentation.cs`) | 표현, 각 시스템의 연출 | 새 연출과 표시가 같은 파일에 모인다 | 6 |
| 적 정의·본체(`EnemyDefinition.cs`, `Enemy.cs`) | 적, 보상, 사망 효과, 업그레이드 | 적의 새 특성이 정의와 실행 상태에 붙는다 | 4 |
| 구매 효과(`UpgradeEffect.cs`, `UpgradeModifiers.cs`) | 업그레이드와 적용 대상 | 새 효과 종류마다 대상 규칙과 적용 자리가 늘어난다 | M6에서 생김. M8 실험 E4에서도 바뀜 |
| 출현(`EnemySpawner.cs`) | 출현, 업그레이드, 사망 효과 | 출현 때 확정하는 값이 모인다 | 3. M8 실험 E4에서도 바뀜 |

## 5. 나눌 때 먼저 합의할 것

- World 단계의 순서와, 순서를 지키는 계약. 여러 후보가 같은 자리에 붙는다.
- 콘텐츠 데이터 형식과 노드 저작 툴의 형식. 툴은 이 Reference 밖의 별도 작업이다.
- 실행 값을 언제 확정하는가(조립 때, 출현 때, 공급 요청 때). 새 구매 효과가 어디에 붙는지 정한다.
- 기록(사망, 효과 적중)의 수명과 소비 방식. 화면 담당과 규칙 담당의 약속이다.
- GAME_RULES 16절의 남은 결정. 특히 HQ 유지 범위, 공간, 다인 보상, 저장은 여러 후보의 인수 기준을 바꾼다.
