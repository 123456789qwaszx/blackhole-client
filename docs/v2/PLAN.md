# Reference v2 — 게임 규칙 반영 PLAN

갱신: 2026-09-24 · M0~M5 완료, M6은 착수 조건 확인 전

## 1. 목적과 기준

6인 팀이 시스템의 흐름·상태 소유권·접점을 이해하고 업무를 나누기 위한 개인 Reference다. 팀에 이식할 완성 코드나 전체 게임을 선행 제작하지 않는다.

기준은 [GAME_RULES](../GAME_RULES.md)다. 확정 규칙, 현재 설계 방향, 레퍼런스 관찰·추정을 구분한다. 관찰·미정 항목을 승인된 게임 규칙으로 올리지 않는다.

v1은 `reference-v1` 태그와 [v1 예제집](../v1/SYSTEM_CATALOG.md)에 보존한다. 현재 v2를 다시 지우지 않는다. 검증된 Player·HQ·행동·수치·스킬 경계를 유지하고 달라진 연결만 바꾼다.

## 2. 실제 진행 상태

- 커밋: M1 `e62c222`, M2 `664d8f4`, M3 `85e34bc`, M4 `38b41ea`(보완 `050fa55`, 서식 정리 `b22e7af`, 결과 기록 `ead5b59`). M5는 결과 기록과 함께 한 커밋.
- PlayerState는 Gold를, HQ는 위치·누적 EXP·Level을 가진다. 구매는 아직 없다.
- 사망: HP <= 0에서 즉시 확정 → Gold·HQ EXP·사망 기록 1회 → 목록 제거. 화면은 사망 기록으로 흡수 연출을 한다.
- 공급: 판 시작 배치 + 성장 공급. 주기 생성은 없다. 성장하면 Level마다 적이 추가되고 판 시간이 늘어난다.
- Step은 이동 → Skill(피해·사망·보상·Level) → 성장 진행(공급 요청·시간 연장) → 공급된 적 생성이고, 종료 판정은 그 뒤다.
- 실행 수치 계산기는 존재하지만 구매 보정 연결은 없다(M6).
- 계약 45개. CoreSmoke와 Unity EditMode가 같은 계약을 실행한다.
- 상세 파일별 차이: [RULES_ALIGNMENT](RULES_ALIGNMENT.md).

## 6. 범위 제한과 착수 조건

- 포함: 사망·보상, HQ 성장의 최소 경계, 구간별 공급 샘플, 메모리 내 구매 루프, 사망 효과 하나.
- 제외: 캐릭터 전투, HQ HP/패배, 네트워크, 다인 보상/공유 적 보정 정책, 영구 저장, 두 번째 플레이어 스킬, 범용 능력치·효과 엔진, 전체 트리·밸런싱.
- 레벨별 전멸·흡수와 추가 보상은 미확인이다. 구현하지 않는다.
- M5의 성장 공식·시간 연장·공급 정책, M6의 HQ 유지 범위·샘플 노드, M7의 효과는 실제 기획 또는 명시적인 임시 샘플로 확인 후 구현한다.
- 미정이 많으면 해당 확장을 보류하고 완료된 경계를 M8 문서로 넘길 수 있다. 확정하지 않은 기능을 구현 완료처럼 기록하지 않는다.

## 7. 임시 값과 기존 동작의 처리

값은 `BlackHole.Sample/SampleContent`, 표현 값은 `SamplePresentation`에 둔다. 수치가 아닌 임시 의미·정책은 이 표와 해당 마일스톤에 표시한다. Core에 샘플 값을 박지 않는다.

| 항목 | 현재/후속 처리 |
|---|---|
| 전투 시간, HQ 위치, 적/스킬 기본 수치 | 기존 샘플 유지 |
| HQ 기준 거리·각도·Orbit 거리 유지 | 샘플 유지. HQ 크기와 연계는 미정 |
| 타이머 생성·최대 수에서 건너뜀 | M5에서 제거. 판 시작 배치 + 성장 공급으로 교체 |
| 생성 시 수치 확정 | 확정 규칙. 임시 목록에서 제외 |
| 중심 기준 피격 | 임시 유지. M6 크기 효과 검증 전에 겹침 규칙 결정 |
| 조준점 없음 = 빈 틱 | 임시 유지 |
| 보상 Gold/HQ EXP, 흡수 길이 | M4 샘플(light 2/1, heavy 5/3, 흡수 0.55초) |
| 일시정지 중 흡수 연출 | 실제 시간으로 계속 진행([임시]). 일시정지 시 연출 처리는 미정(GAME_RULES 13절) |
| EXP 임계값, 구간별 공급·시간 연장 | M5 샘플: 시작 30초, 시작 light 8·heavy 2, 성장마다 light 6·heavy 1·+5초, 임계값 Lv2 6 ~ Lv10 126 |
| HQ 표현 크기 | 표현 샘플: 지름 1.3, Level마다 +0.15. 출현 거리는 바꾸지 않음 |
| 노드·가격·보정량, HQ 유지/초기화 | M6 확인 전 미입력 |
| 사망 효과 종류·반경·피해 | M7 확인 전 미입력 |

## 8. 작업과 검증

1. 다음 마일스톤의 범위와 남은 결정부터 검토한다.
2. 구현하고 관련 계약을 갱신한다. 바뀐 규칙의 옛 기대값만 유지하지 않는다.
3. CoreSmoke, 가능한 환경에서 Unity와 같은 어셈블리 경계 빌드, 필요한 핵심 변이 검사를 한다.
4. 사용자 Unity 플레이 확인 후 결과·PLAN 재점검을 기록한다.
5. 의미 있는 마일스톤 변경과 관련 씬·기록을 하나의 커밋으로 묶는다.
6. 다음 마일스톤 진행 확인을 받는다.

검증하지 못한 환경은 기록한다. 기존 작업자의 Windows 경로·열린 Unity 상태를 다른 환경에 그대로 적용하지 않는다. 기여자 표기는 실제 작성자를 기준으로 한다.
