# M6 — 전투 밖 구매와 다음 전투

상태: 완료(2026-09-24) · 선행: M5 · 메모리 내 진행만. 영구 저장 제외

## 목표

적 정리 → Gold로 노드 구매 → 구매 상태 유지 → 새로운 전투/적에 보정 적용의 실제 흐름을 검증한다.

근거: [GAME_RULES](../GAME_RULES.md) 8·13·14절, [레퍼런스 분석](../REFERENCE_ANALYSIS.md) 7절.

## 툴과 게임의 경계 (2026-09-24 확인)

노드 저작 툴은 이 Reference 밖의 별도 작업이다. 두 쪽은 **노드 데이터 형식** 하나로 이어진다.

| 구분 | 담당 | 내용 |
|---|---|---|
| 노드 저작 툴(별도) | 툴 | 노드 배치·위치, 연결 편집, 구역·색 표시, 대량 편집, 데이터 내보내기 |
| 노드 데이터 형식 | 툴과 게임의 약속 | 노드 ID, 가격, 선행 노드, 보정 목록(종류 + 값) |
| 게임 런타임 | Core | 로드와 검증, PlayerState의 Gold·구매 상태, 구매 규칙, 구매 효과의 적용 |
| 구매 화면 | Unity 표현 | M6에서는 확인용 목록. 공간 배치 트리 화면은 만들지 않는다 |

노드의 위치와 구역은 툴과 화면의 정보다. Core는 해석하지 않는다.

## 노드 데이터 형식

```text
Upgrades[i]
  Id         노드 ID(유일)
  Price      Gold 가격(양의 정수)
  Requires   선행 노드 ID. 비어 있으면 처음부터 살 수 있다
  Effects[j] 보정 목록
    Kind     효과 종류(아래 표)
    Value    값
    Target   대상 ID. Skill 효과는 Skill ID(필수), 공급 효과는 Enemy ID(필수),
             적 수치·보상 효과는 Enemy ID(비우면 모든 종류)
```

| Kind | 적용 대상 | 적용 시점 |
|---|---|---|
| SkillDamageAdd | 대상 Skill의 피해량 + Value | 전투 조립 때 |
| SkillRadiusAdd | 대상 Skill의 반경 + Value(화면 원도 같은 값) | 전투 조립 때 |
| SkillIntervalMultiply | 대상 Skill의 주기 × Value | 전투 조립 때 |
| EnemyHealthMultiply | 출현하는 대상 적의 HP × Value | 출현 때 |
| GoldMultiply | 대상 적의 Gold 보상 × Value | 출현 때 |
| HqExpMultiply | 대상 적의 HQ EXP 보상 × Value | 출현 때 |
| GrowthSupplyAdd | 성장 공급에서 대상 Enemy의 수 + Value(정수) | 공급 요청 때 |

- 기존 효과 종류로 노드를 추가할 때는 데이터만 바뀐다.
- 새 효과 종류는 종류 이름, 로더의 해석, 그 효과를 받는 시스템의 적용 자리를 하나씩 더한다.
- 범용 효과 엔진(조건식, 효과 그래프)은 만들지 않는다.

## 이 마일스톤에서 정하는 것 (구조상 선택, [임시] 표시)

- **선행 노드:** 노드마다 하나다. 선행이 여러 개일 때의 AND·OR 정책은 미정이라 만들지 않는다.
- **효과 적용 순서:** 콘텐츠의 노드 순서를 따른다. 산 순서와 무관하게 같은 결과가 나온다.
- **보상 보정의 정수 처리:** 보정된 Gold·HQ EXP는 올림한다 [임시].
- **전투 중 구매 금지:** PlayerState가 진행 중인 전투에 들어가 있으면 구매를 거부한다. 전투가 끝나면 풀린다.
- **다인 판:** 적·보상·공급에 영향을 주는 구매를 가진 Player가 있는 다인 판은 조립 때 거부한다. 공유 적에 다인 구매를 합치는 정책이 없기 때문이다(M4의 보상 정책 부재와 같은 방식).
- **Skill 효과의 대상:** 효과가 대상 Skill을 지정한다. Skill은 각자 자기 특성(기준점, 수치)을 가진 개별 존재이므로 강화도 개별 Skill에 붙는다(사용자 확인). Player가 그 Skill을 가지고 있을 때만 적용된다.
- **구매 기록:** PlayerState는 산 노드를 노드 ID로 기록한다. 콘텐츠를 다시 불러와도 진행이 이어지고, 나중에 저장할 때도 ID가 그대로 쓰인다. 전투를 조립할 때 ID를 콘텐츠의 노드로 해석한다.

## [임시] 샘플 트리

```text
breaker-damage  sample-aura 피해 +2                   10G
 ├─ breaker-radius  sample-aura 반경 +0.3              15G
 │   └─ growth-supply  성장마다 light +2               25G
 ├─ breaker-speed  sample-aura 주기 ×0.8               20G
 │   └─ golden-touch  Gold ×1.5                       40G
 └─ dense-matter  적 HP ×1.5, Gold ×1.5, HQ EXP ×1.5    30G   ← 질량 = HP·보상의 샘플 보정
```

한 전투 수입은 전부 처치하면 100 Gold 안팎이다(시작 배치 26 + 성장 1회마다 17).

## 범위와 소유권

- Gold·구매 노드는 PlayerState의 진행 데이터다. World·적·스킬 타이머·조준점은 새 전투 실행 상태다.
- SessionAssembler가 진행 데이터를 받아 새 실행 상태를 만든다. 기존 종료 결과는 스냅샷으로 고정한다.
- 종료 → 적/연출 정리 → 구매 화면 → 다음 전투 순서를 한 곳에서 조립한다.
- 전투 중 구매를 허용하지 않는다. 구매 실패 시 Gold/노드 상태가 부분 변경되지 않는다.
- 스킬(피해/반경/주기), 생성 적 수치, 공급 수량, 보상에 최소 구매 보정 예제를 연결한다.
- 적 수치와 구매 보상 보정은 생성 시 스냅샷으로 확정한다. 공유 기본 정의는 바꾸지 않는다.
- 스킬 수치는 다음 전투 조립에 구매 결과를 반영한다.
- 질량은 공식이 없으면 별도 엔진 없이 HP·보상의 명시적 샘플 보정으로만 검증한다.
- 제외: 노드 저작 툴, 공간 배치 트리 화면, 구역 잠금 규칙, 크기 업그레이드, 전체 트리와 밸런싱.

## 완료 기준

- 처치로 번 Gold로 구매하고 다음 전투에서 해당 변화가 실제 발생.
- 구매 실패/중복/선행 미충족 시 재화·구매 상태가 의도치 않게 변경되지 않음.
- 새 전투의 시간·Enemy·AimPoint·Skill 타이머는 새 상태, Gold·구매는 유지.
- 이전 전투의 적/연출/사망 기록을 구매 화면과 새 전투로 가져오지 않음.
- 새 진행 리셋은 구매 유지 전환과 구분되고 종료 결과가 소급 변경되지 않음.
- 두 Player의 구매 상태 독립성을 단위 검증. 공유 적에 다인 구매를 합성하는 정책은 만들지 않음.
- 잘못된 노드 데이터(중복 ID, 없는 선행 노드, 선행 순환, 알 수 없는 효과 종류, 잘못된 값)는 경로와 함께 보고.
- 사용자 플레이로 전투 → 구매 → 다음 전투를 확인.

## 결과

완료: 2026-09-24

**한 일**

- `Upgrades/`
  - `UpgradeEffectKind`(효과 종류 7개), `UpgradeEffect`(종류, 값, 대상 Skill 또는 Enemy). 대상 규칙은 `TargetsSkill`, `RequiresEnemy` 한 곳에 있다.
  - `UpgradeNodeDefinition`(ID, 가격, 선행 노드 하나, 효과 목록). 위치·구역 같은 배치 정보는 없다.
  - `UpgradePurchase`(Check, TryPurchase): 전투 중, 이미 산 노드, 선행 미충족, Gold 부족이면 실패하고 상태를 바꾸지 않는다.
  - `UpgradeModifiers`: 효과 종류마다 적용 자리가 하나다. Skill 수치(조립 때), 적 HP(출현 때), 보상(출현 때, 배율을 모두 곱한 뒤 올림), 성장 공급량(공급 요청 때). 효과는 콘텐츠의 노드 순서로 쌓인다.
- 진행과 전투의 분리
  - `PlayerState`: Gold, 산 노드 ID, 전투 잠금(`InBattle`). 공개 생성자로 호스트가 진행을 만든다.
  - `Player`: 전투마다 새로 만들고 PlayerState를 참조한다.
  - `SessionAssembler.Create`는 새 진행, `CreateBattle`은 기존 진행을 이어 받는 다음 전투다. 모든 검사를 통과한 뒤에만 PlayerState를 전투에 들인다. 전투가 끝나면(`GameSession.End`) 풀린다.
  - 적·보상·공급에 영향을 주는 구매가 있는 다인 판은 조립 때 거부한다.
- `EnemyReward`: 적의 실행 보상. 출현 때 확정하고 사망 때 이 값으로 지급한다.
- 공급: `SupplySource`(Start, Growth). 구매한 성장 공급 보정은 성장 공급에만 더해진다.
- Content: `Upgrades`(Id, Price, Requires, Effects[Kind, Value, Target])를 2단계로 읽는다. 효과 종류는 열거형 이름으로 해석한다. 노드 사이의 규칙(ID 유일, 선행 실재, 순환)은 ContentInvariants가 본다.
- Sample: 위 [임시] 샘플 트리.
- Unity
  - `SessionLauncher`가 진행의 수명을 가진다. 새 진행, 전투 종료 → 적·연출 정리 → 구매 화면, 다음 전투를 모두 여기서 한다.
  - HUD: 전투 표시와 구매 화면(노드 목록, 구매 버튼, Next battle, New run). R은 새 진행이다.

**발견**

- 노드 저작 툴과 공간 배치 트리 화면은 이 Reference 밖의 별도 작업으로 분리했다. 두 쪽을 잇는 것은 노드 데이터 형식 하나다(사용자 확인).
- Skill 효과는 모든 Passive Skill이 아니라 대상 Skill에 붙는다. Skill은 각자 특성을 가진 개별 존재이고, 이 게임에는 액티브 스킬이 없을 뿐이다(사용자 확인).
- 구매를 노드 ID로 기록했다. 그래서 보상이 없는 같은 모양의 콘텐츠로 다인 계약을 만들 수 있었다. 산 노드가 없는 콘텐츠로 조립하면 오류다.
- 전투 잠금이 필요했다. 전투 중 구매 금지와, 한 PlayerState가 두 전투에 들어가는 일을 같은 상태로 막는다.
- 효과 적용 순서(콘텐츠 순서)는 지금 샘플에서 같은 수치에 더하기와 곱하기가 섞이지 않아 결과 차이가 드러나지 않는다. 섞이는 노드가 생기면 계약을 추가한다.

**계획과 달라진 점**

- Skill 효과의 대상을 "모든 Passive Skill"에서 "대상 Skill"로 바꿨다(사용자 지적).
- 구매 기록을 정의 객체가 아니라 노드 ID로 했다.
