# M5 — HQ 성장과 진행 구간·적 공급

상태: 완료(2026-09-24) · 선행: M4 · 착수 조건 확인(2026-09-24)

## 목표

HQ EXP → Level과 구간 도달 → 시간 연장·적 공급의 경계를 최소 예제로 확인한다. 레퍼런스 내부 규칙을 복제했다고 주장하지 않는다.

근거: [GAME_RULES](../GAME_RULES.md) 4·9절, [레퍼런스 분석](../REFERENCE_ANALYSIS.md) 2~4절.

## 착수 조건 (2026-09-24 확인)

| 착수 전에 정할 것 | 정한 내용 | 근거 |
|---|---|---|
| EXP 임계값, 일반 레벨업과 특별 구간의 관계 | Level마다 필요 누적 EXP가 늘어난다. 효과(시간 연장, 적 공급)는 Level마다 콘텐츠 값으로 둔다. 모든 Level이 같은 효과라고 가정하지 않으면서, 레퍼런스처럼 매 성장에 효과를 줄 수 있다 | 레퍼런스: 성장할 때마다 소행성 추가와 시간 증가(사용자 확인). GAME_RULES 9절 |
| 시작 배치, 구간별 추가 수량·종류, 시간 연장량 | 아래 [임시] 샘플. 주기 생성은 제거한다 | 레퍼런스: 유한한 시작 배치, 주기 생성 근거 없음 |
| 같은 단계의 처치·구간 도달·시간 종료 우선순위 | 처치 → EXP·Level → 성장 효과(공급 요청, 시간 연장) → 공급된 적 생성 → 종료 판정. 마지막 단계의 처치로 도달한 성장도 시간을 늘린다 | 사용자 결정 |
| 추가 적이 해당 단계에 즉시 맞는지 | 기존 규칙을 따른다. 한 단계에 나온 적은 다음 단계부터 움직이고 맞는다 | M2 이후 World 단계 규칙 |
| HQ 시각 크기만 바꿀지, 생성 거리도 바꿀지 | 시각 크기만 바꾼다. 화면이 Level을 읽어 그린다. 출현 거리는 콘텐츠 값 그대로이고 공간 공식은 넣지 않는다 | 레퍼런스: 화면만 커짐. GAME_RULES 12절 |

추가로 확인한 것:
- **Level 유지:** HQ Level은 판마다 1부터 시작한다(지금의 조립 방식). 레퍼런스도 판마다 초기화되는 것으로 보인다. 전투 사이 유지 범위의 결정은 M6 착수 조건이다.
- **공급량과 M6:** 레퍼런스는 성장 때 추가되는 소행성 수를 초반 노드로 늘린다. 그래서 공급량이 실제 생성 수가 되는 자리를 한 곳에 둔다. M6에서 구매 보정이 그 자리에 붙는다. 보정 구조는 M5에서 만들지 않는다.
- **제외:** 이름 붙은 Milestone의 특수 효과(전체 흡수 등)는 레퍼런스에서도 확인되지 않았다. 넣지 않는다.

## [임시] 샘플

| 항목 | 값 |
|---|---|
| 시작 시간 | 30초 |
| 시작 배치 | light 8, heavy 2 |
| 성장 1회마다 | light 6, heavy 1 추가, 시간 +5초 |
| Level 임계값(누적 EXP) | Lv2 6, Lv3 14, Lv4 24, Lv5 36, Lv6 50, Lv7 66, Lv8 84, Lv9 104, Lv10 126 |

- 적 보상은 M4 값을 쓴다(light EXP 1, heavy EXP 3).
- 업그레이드가 없는 지금은 전부 처치해도 Lv6 근처에서 멈춘다. 더 멀리 가는 것은 M6에서 구매로 늘린다.

## 범위

1. HQ 성장 상태(누적 EXP, Level)와 공유 성장 정의(Level 노드)를 분리한다. 샘플 임계값을 쓴다.
2. 구간 효과는 진행 처리에 둔다. HQ가 직접 적을 생성하거나 타이머를 바꾸지 않는다.
3. 공급 구성 결정과 실제 생성을 분리한다. 시작 배치와 구간 추가를 쓰고, 종전 자동 주기 생성은 제거한다.
4. 판마다 시간 예산을 두고 늘린다. 공유 TimeLimitDefinition은 바꾸지 않는다.
5. 성장을 화면에 표시한다(HQ 크기, HUD의 Level·EXP). 전체 적 흡수·전멸은 규칙이 미정이므로 구현하지 않는다.
6. Content 검증, Sample, 출현·시간·스킬·사망 계약을 함께 갱신한다.

## 완료 기준

- 초기 배치는 1회. 도달한 구간의 공급·시간 효과도 1회.
- EXP가 여러 임계값을 넘는 경우 각 해당 구간을 중복·누락 없이 처리.
- 긴 프레임과 짧은 프레임에서 같은 구간 진행 결과. 임계값 전·같음·후 확인.
- 시간 연장 후에도 종료·진행 제한이 같은 시간 원본을 사용.
- 같은 콘텐츠로 만든 두 세션의 시간·HQ·공급 상태는 독립.
- 첫 틱 0초는 유지하되, 초기 적이 생긴 새 조건에 맞는 실제 피해를 검증.
- 사용자 확인: 성장 표시, 공급, 시간 연장, 종료.

## 비범위와 결과

구매, 영구 저장, HQ 전투 능력, 전체 전멸, 실제 게임의 밸런스 복제는 제외한다.

## 결과

완료: 2026-09-24

**한 일**

- 공급과 생성의 분리
  - `Supply/`: `SupplyRequest`(종류·수량), `EnemySupply`(요청을 모아 단계 끝에 생성). 요청 수량이 실제 생성 수가 되는 유일한 자리이며, M6의 공급량 보정이 여기에 붙는다.
  - `Spawn/`: `EnemySpawner.Spawn`(HQ 기준 위치, 출현 때 수치 확정, 행동). `SpawnDefinition`은 거리와 각도 간격만 가진다.
  - 주기 생성, 동시 최대 수, 종류 순서를 제거했다.
- 전투 시작 배치: 판 조립 때(0초) `StartSupply`를 공급한다.
- HQ 성장
  - `HqGrowthDefinition`: Level 노드 목록. 노드마다 임계값, 연장 시간, 추가 공급을 가진다.
  - `Hq`: 누적 EXP, Level, 다음 임계값. 한 번의 획득으로 여러 Level을 오른다.
- 성장 진행: `GrowthProgression`이 새로 도달한 Level을 낮은 것부터 한 번씩 처리한다. 처리할 때 공급을 요청하고 판 시간을 늘린다.
- 판 시간: `TimeLimitRule.Limit` = 공유 정의의 시간 + 이 판의 연장. 진행 제한, 종료 판정, 남은 시간이 같은 값을 쓴다. 공유 정의는 바뀌지 않는다.
- World 단계: 이동 → Skill(피해·사망·보상·Level) → 성장 진행 → 공급된 적 생성. 종료 판정은 SessionRunner가 단계 뒤에 한다.
- Content
  - `StartSupply`, `Growth.Levels`(Exp, ExtraTime, Supply)를 추가했다.
  - 로더는 두 단계로 읽는다. 공급·성장 노드의 Enemy 참조는 1단계의 Enemy 색인으로 해석하며 경로와 함께 진단한다.
  - `DefinitionGuard.NonNegative`를 추가했다(연장 시간).
- Sample: 위 [임시] 샘플.
- Unity: HQ 원판이 Level마다 커진다(표현 샘플). HUD에 Level, EXP, 다음 임계값.
- 계약: 8개 추가(Growth 7, Content 1). 합계 45개.
  - 초기 배치 기준으로 기존 Skill·Death·Enemy·Content 계약의 입력과 기대값을 고쳤다.
  - 이름을 바꾼 계약: `Enemy.StartPlacementAroundHqAtDistance`, `Enemy.LongFrameMovesLikeShortFrames`, `Enemy.SupplyCreatesKindsInRequestOrder`.
- [레퍼런스 분석](../REFERENCE_ANALYSIS.md) 문서를 추가했다.

**발견**

- 착수 조건은 추상적인 선택지로 묻기 전에 레퍼런스를 분석해야 했다. 성장하면 소행성이 추가되고 시간이 늘어난다는 핵심은 사용자 관찰로 확정됐다.
- 초기 배치가 생기자 `Enemy` 공전의 긴 프레임 계약이 시간 분할을 더는 확인하지 못했다. 공전은 각도 계산이라 단계 크기와 무관하기 때문이다.
  - 시간 분할의 확인을 `Growth.LongFrameMatchesShortFrames`로 옮겼다.
  - 분할을 없애면 이 계약이 실패하는 것을 변이로 확인했다.
- 공급과 성장 노드는 Enemy를 정의 객체로 참조한다. 그래서 참조 검사는 ContentInvariants(ID 문자열)가 아니라 로더의 2단계 해석에서 한다. GameContent 생성자 보장 문구도 고쳤다.
- 성장 진행이 판 시간(TimeLimitRule)을 참조한다. 시간은 Session의 상태지만, 단계 안에서 늘어나야 종료 판정 전에 반영되므로 조립 때 참조를 넘긴다.
- Level 표기: 시작 Level은 1이고 `Growth.Levels[i]`는 Level (i + 2)다. 표기 방식일 뿐 규칙이 아니다.
