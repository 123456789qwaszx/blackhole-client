# M2 — Enemy: 정의, Runtime Stat, 출현, Orbit 행동

> 2026-09-24 규칙 갱신: 아래 본문과 결과는 완료 당시 기록이다. 현재 지시는 [PLAN](PLAN.md)과 [GAME_RULES](../GAME_RULES.md)를 따른다. 주기 생성은 당시 임시 정책이며 M5에서 공급 결정과 생성 실행을 분리한다. 생성 시 수치 확정은 이제 확정 규칙이다. 구매 보정 연결은 M6, 사망 효과는 M7, 최종 실험은 M8이다.


상태: 완료(2026-09-24) · 선행: M1 · 결정 D3 승인

## 목표

Enemy가 HQ 주변에 나타나 HQ 주위를 돈다. Enemy는 종류별로 다르고, 기본 정의와 실행 수치가 분리되어 있으며, 행동은 본체 밖에 있다. 아직 아무도 Enemy를 공격하지 않는다.

## 검증할 경계

- **B2 HQ 기준점**: 출현 위치와 Orbit 중심이 HQ 위치에서 온다. HQ를 옮긴 판에서는 출현과 공전이 새 위치를 따라간다.
- **B3 행동 분리**: Enemy 본체는 "행동이 무엇인지" 모른다. 행동은 현재 상태를 받아 다음 위치를 정한다. 위치의 원본은 Enemy 하나이고, 화면은 읽기만 한다.
- **B4 Runtime Stat 분리**: 종류 정의(기본 수치)와 실행 수치가 다른 개념이다. 실행 수치 = 기본 정의 + 보정. 지금은 보정이 없다(항등).
- **B9 Content**: Enemy 종류 정의와 출현 설정의 검증.

## 범위

- Enemy 종류 정의: HP, 이동 속도, 크기, 보상 Gold/EXP(값만 두고 지급은 M4). 행동 종류 참조.
- Enemy 실행 상태: 현재 HP, 위치, 생존 여부, 실행 수치.
- Runtime Stat 계산: 기본 정의와 보정 목록을 받아 실행 수치를 만든다. 계산 시점은 [임시]로 출현 때 1회.
- 행동: Orbit Around HQ 하나. 행동 종류를 해석하는 자리는 한 곳.
- 출현: HQ 기준 거리, 주기, 동시 최대 수. 종류 선택은 가장 단순한 방식.
- 화면: Enemy를 종류별 외형으로 그린다(표현 정의에 둔다. v1 패턴).
- 행동 교체 가능성 증명(D3): 게임 콘텐츠에는 Orbit 하나만 두고, 콘텐츠의 종류 해석에도 가짜 행동을 추가하지 않는다. 계약 테스트가 행동 경계(예: 행동 인터페이스)에 작은 Fake를 직접 꽂아, Enemy가 Orbit 구현에 종속되지 않았음을 보인다. Fake를 꽂을 수 있는 자리를 어떻게 열지(조립 시 주입 등)는 이 마일스톤에서 정하고 결과에 남긴다.

## 비범위

- 피해, Death, 보상 지급(M3·M4).
- 종류별 고유 능력(보호막, 분열 등), 사망 효과.
- AI 상태 기계, 행동 전환, 추적.
- 난이도 증가 공식, PlayerState 기반 보정(자리만 둔다).

## [임시] 값

- Enemy 종류 2종과 기본 수치.
- Orbit 속도·반경(또는 접근 방식).
- 출현 주기, 동시 최대 수, HQ로부터의 거리.
- Runtime Stat 계산 시점: 출현 때 1회.

## 이 마일스톤에서 확인할 질문

- Orbit의 "HQ 주위를 빙글빙글"은 반경이 고정인가, 천천히 다가오는가? 가이드는 공전만 말한다. 가장 단순하게 고정 반경 공전으로 두고 [임시]로 표시한다.
- 여러 종류의 Enemy가 같은 행동을 쓸 때, 수치 차이는 행동 정의에 두는가 Enemy 종류에 두는가? 이동 속도는 Enemy 수치(가이드 6절)이므로 Enemy 쪽에 두고, 행동은 그 수치를 읽는다.

## 작업 순서

1. Enemy 종류 정의와 로더·진단.
2. Runtime Stat 계산(보정 자리, 항등).
3. Enemy 실행 상태와 Enemy 목록.
4. 행동 분리와 Orbit Around HQ.
5. 출현.
6. 화면과 표현 정의.
7. 계약 테스트(Enemy, 행동, 출현, Runtime Stat).

## 완료 기준

- **자동 계약**
  - Enemy가 HQ 기준 거리에 나타나고 HQ를 중심으로 돈다. HQ 위치를 바꾸면 따라간다.
  - 긴 프레임도 단계로 나뉘어 진행된다(M1에서 관찰할 수 없던 시간 분할을 이동으로 확인한다).
  - 테스트의 Fake 행동이 Enemy 본체·출현·Session을 고치지 않고 연결되고, 게임 콘텐츠와 종류 해석에는 Fake가 없다.
  - 실행 수치는 기본 정의에서 계산되고, 보정을 넣으면 기본 정의는 그대로인 채 실행 수치만 바뀐다(테스트용 보정).
  - 같은 정의로 만든 두 판의 Enemy가 상태를 공유하지 않는다.
  - 잘못된 Enemy 정의는 경로와 함께 보고된다.
- **플레이 확인**: 두 종류의 Enemy가 HQ 주변에 나타나 공전한다. 종류별 외형이 다르다.

## 재점검 항목

- 행동이 Enemy 본체의 필드나 분기로 새지 않았는가?
- 실행 수치를 여러 곳이 각자 고치고 있지 않은가(원본은 기본 정의 + 보정)?
- 출현이 Enemy의 행동까지 책임지고 있지 않은가?
- M3의 Skill이 Enemy를 찾고 피해를 요청할 자리가 있는가?

## 결과

완료: 2026-09-24

**한 일**

- `Enemies/`
  - EnemyDefinition(기본 수치 + 행동 정의), EnemyStats(기본·실행 수치가 같은 모양)
  - EnemyStatCalculator와 IEnemyStatModifier(실행 수치 = 기본 + 보정, 순서대로)
  - Enemy(위치·HP·실행 수치의 원본. 행동 경계만 안다)
  - IEnemyBehavior·EnemyBehaviorInput, OrbitHqBehavior, EnemyBehaviors.Standard(행동 해석의 유일한 자리), EnemyBehaviorResolver
- `Spawn/`: SpawnDefinition, EnemySpawner(타이머·순번, 출현 때 실행 수치 계산).
- World: Enemy 목록과 ID 발급. 단계 순서는 이동 → 출현.
- Content: Enemy·출현 데이터, 로더 섹션, ContentInvariants(Enemy ID 유일, 출현 순서의 실재).
- SessionAssembler: 행동 해석기를 받는 두 번째 조립 경로(D3). 게임은 Standard 경로를 쓴다.
- Sample: Enemy 2종(`sample-light` 반시계, `sample-heavy` 시계), 출현 설정.
- Unity: WorldView가 Enemy를 게임 수치 크기로 그리고, 종류별 색은 SamplePresentation에서 가져온다(없으면 기본 색). HUD에 Enemy 수.
- 계약 10개 추가(Enemy 8, Content 2). 합계 22개.

**검증**

- CoreSmoke 22개 통과.
- 시간 분할을 일부러 없애면 `Enemy.LongFrameIsSteppedLikeShortFrames`가 실패한다. M1에서 관찰할 수 없던 시간 분할을 이 계약으로 확인했다.
- Unity와 같은 경계로 나눈 컴파일: 경고 0, 오류 0.
- Enemy·World·출현 코드에 "Orbit"이 나오지 않는다. 원점 가정(`Point2(0, 0)` 등)이 코드에 없다.
- 사용자 플레이 확인: 출현, 종류별 색·크기·방향, 최대 수, 일시정지, 재시작, 재활성화, EditMode 22개.

**발견**

- 행동 교체 자리(D3)는 판 조립 때 해석기(`EnemyBehaviorResolver`)를 넘기는 방식으로 정했다. 콘텐츠의 종류 이름에는 Fake가 없고, 테스트만 해석기를 바꾼다.
- 보정 자리는 계산 한 곳(`EnemyStatCalculator`)에 두었다. 게임에서는 보정의 출처가 미정이라 빈 목록을 넘긴다. 보정을 실제로 연결하는 실험은 M5에서 한다.
- 긴 프레임 계약을 처음에 정확히 3.0초로 잡았다가, 부동소수 누적 차이로 두 경로의 출현 수가 갈렸다. 출현 시각과 겹치지 않는 3.5초로 옮겼다. 시간 경계에 걸친 계약은 경계에서 떨어진 시각을 쓴다.

**계획과 달라진 점**

- 보상 Gold/EXP 필드는 M4로 미뤘다. 지금은 쓰이지 않아서 "없어도 돌아가면 채우지 않는다"(PLAN 5절 정책 1)를 따랐다.
- 새 [임시] 규칙: Orbit은 "HQ로부터 거리 유지"로 해석했다. 이동 속도는 Enemy 수치로, 회전 방향은 행동 정의의 값으로 두었다. 출현은 판 시작 후 주기마다 한 번이고, 동시 최대 수에 걸린 출현은 미루지 않고 건너뛴다. PLAN 5절 표에 반영했다.
