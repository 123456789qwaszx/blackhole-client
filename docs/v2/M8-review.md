# M8 — 변화 실험과 정리

상태: 계획 · 선행: M7 (보류된 확장은 미구현으로 명시)

## 목표

만든 경계가 실제 변화에 버티는지 작은 실험으로 확인하고, 결과를 팀이 쓸 수 있는 문서로 정리한다. v1에서 가장 쓸모 있었던 "변화가 어디까지 번지는가"를 v2 규칙 기준으로 다시 본다.

## 변화 실험

각 실험은 바뀐 파일과 바뀌지 않은 파일을 기록한다. 실험용 변경은 테스트 콘텐츠에만 두고, 게임 규칙으로 남기지 않는다.

| 실험 | 확인할 것 | 관련 경계 |
|---|---|---|
| 수치만 다른 Enemy 종류 추가 | 콘텐츠만 바뀌는가 | B4, B9 |
| Enemy Runtime Stat에 보정 하나 연결(예: 테스트용 HP 배율) | 기본 정의·Enemy 본체·출현이 바뀌지 않는가 | B4 |
| Skill 수치에 보정 하나 연결(예: 반경 증가) | 공격 범위와 화면 원이 함께 바뀌는가 | B5, B7 |
| Skill 기준점을 다른 것으로 교체(예: HQ 위치) | Skill 실행 구조가 바뀌지 않는가 | B5 |
| Player 2명으로 판 조립(테스트) | 전역 Player 가정이 어디에 남았는가. 보상 귀속 정책이 없다는 사실이 약속대로 드러나는가 | B1, B6 |
| AimPoint를 다른 출처로 채움(예: HQ 위치를 AimPoint로) | Skill·Player가 마우스를 모르는가 | B1, B5 |
| 흡수 연출을 끄거나 길이를 바꿈 | 보상과 게임 결과가 바뀌지 않는가 | B7 |

## 정리할 문서

- **v2 예제집**: v1 SYSTEM_CATALOG처럼 시스템 후보별로 목적, 핵심 흐름, 만들며 부딪힌 질문([구조]/[임의]), 기획이 정할 규칙, 접점, 변화 실험 결과를 적는다.
- **GAME_RULES 갱신**: 만들며 생긴 새 질문과, 사용자가 답한 것을 반영한다.
- **[임시] 값 목록**: 최종 상태로 정리한다. 무엇이 여전히 미정인지 한눈에 보이게 한다.
- **규모 측정**: 목표 대상 수가 정해졌으면 그 수로 Core 비용을 잰다(Unity 측정은 별도).

## 비범위

- 새 게임 규칙 추가.
- 실험 결과를 게임 콘텐츠에 남기기.

## 완료 기준

- 실험마다 바뀐 곳과 바뀌지 않은 곳이 기록되어 있다.
- v2 예제집과 GAME_RULES가 최신이다.
- 전체 PLAN의 재점검 기록이 M0~M8 모두 채워져 있다.

## 재점검 항목

- v2가 PLAN 1절의 목적(경계의 체감)을 달성했는가?
- 남은 미정 항목 중 다음에 기획이 먼저 정해야 할 것은 무엇인가(HQ 유지 범위, 공간 연계, 노드 밸런스, 영구 저장 등)?
- 다음 단계가 Reference 확장인지, 팀 설계로 넘어가는 것인지.

## 최신 규칙 추가 실험과 팀 분배 산출물

- 생성 공급 구간 추가: 적 본체/행동을 고치지 않고 구성 변경.
- HQ 성장 임계값 변경: 구매 해금과 독립적인지 확인.
- 구매 → 다음 전투의 스킬/적/공급/보상 변화와 기본 정의 불변.
- 두 Player의 조준점·스킬·구매 상태 독립성은 보상 거부 테스트와 별개로 검증.
- 사망 효과 하나의 변화가 구매·세션·표현에 어디까지 전파되는지 기록.
- 연출 생략과 공간 정리가 처치 보상을 바꾸지 않는지 확인.
- 후보 시스템별 목적·소유 상태·입출력·선행 작업·독립 검증 방법·인수 기준·공동 수정 지점을 표로 정리한다.
- 예상 소요 시간은 구현 기록과 팀 경험을 근거로 범위를 제시한다. 담당자와 확정 일정은 임의로 배정하지 않는다.
- 목표 수량이 없으면 성능 목표를 만들지 않는다. 측정 환경과 Core/Unity의 범위를 구분한다.
- Reference를 계속 확장하기보다 이 자료로 팀 설계와 티켓 분배에 넘어갈 수 있는지 확인한다.
