## 1. 먼저 알아둘 것

- 이 레포는 학습 자료다. 시스템마다 흐름, 목적, 규칙, 상태의 주인, 접점을 체감하려고 만들었다. 코드나 클래스 구성을 팀 레포로 옮기는 것이 목적이 아니다.
- 규칙의 원본은 문서다. 코드는 규칙을 따른 한 가지 구현일 뿐이다.
- 레퍼런스 게임은 "A Game About Feeding A Black Hole"이다. 레퍼런스의 관찰은 우리 게임의 규칙이 아니다. 우리 규칙은 GAME_RULES가 정한다.
- 코드와 문서의 [임시]는 Reference를 돌리려고 정한 값·정책이다. 기획 결정으로 읽으면 안 된다.
- 기획이 정하지 않은 것은 구현하지 않았다. 필요한 경우 [임시]로 표시하고 미정 목록에 남겼다.
- 원칙: 현재는 최대한 단순하게 만든다. 다만 현재의 단순함을 영구적인 제약으로 만들지 않는다(GAME_RULES 1절).

## 5. 게임 규칙 요약

원본: [GAME_RULES](docs/GAME_RULES.md). 분류 표시가 없는 항목은 GAME_RULES가 분류 없이 적은 규칙이다.

> 적을 처치해 플레이어는 구매 재화를 얻고 HQ는 성장한다. 플레이어는 전투 밖에서 업그레이드를 구매하며, 다음 전투의 스킬·적·출현 구성·보상에 구매 결과가 반영된다.

### 5.1 전체 흐름(2절)

1. 구매 상태와 전투 설정으로 새 전투를 준비한다.
2. HQ를 기준으로 적을 배치한다.
3. 적은 행동 규칙으로 움직인다. 현재는 HQ 주변 공전이다.
4. 플레이어의 패시브 스킬이 자기 주기와 조건으로 공격한다.
5. 적의 HP가 0 이하가 되면 사망을 확정하고 보상을 반영한다.
6. 현재 설계 방향: 플레이어에게 Gold, HQ에 성장 EXP.
7. 사망 효과가 있는 적은 게임 효과를 일으키고, 화면은 사망·흡수 연출을 보여 준다.
8. 성장 구간에 따른 시간 연장과 적 추가 공급(검토 중인 진행 방식).
9. 전투를 끝내고 업그레이드 화면으로 갈 때 기존 적을 정리한다.
10. Gold로 노드를 사고 다음 전투에 들어간다.

종료 기준안: 제한 시간이 끝나면 즉시 종료. 멀티플레이 종료는 따로 검토한다.

### 5.2 상태의 소유(3절)

| 상태 | 주인 |
|---|---|
| 위치(공간 기준점) | HQ |
| 성장 EXP·Level | HQ(현재 설계 방향) |
| Gold·구매한 업그레이드 | 플레이어의 PlayerState |
| 조준점 | 플레이어 |
| 스킬 타이머·실행 수치 | 플레이어가 가진 스킬 |
| 종류별 기본 수치·특성 | 적 종류 정의 |
| 현재 HP·위치·실행 수치 | 각 적 |
| 남은 시간·전투 상태·진행 구간 | 전투 세션과 진행 처리 |
| 적 목록 | 적 관리 시스템 |
| 연출 경로·시간·View | Presentation |

책임의 구분이며 클래스나 파일 구성을 강제하지 않는다.

### 5.3 HQ — 블랙홀(4절)

- 확정: 중앙 블랙홀은 본진이자 월드의 기준점인 HQ다. 생성과 행동은 HQ 위치를 참조하고, 좌표 원점을 HQ라고 가정하지 않는다. HQ와 플레이어는 다른 존재다. 적이 블랙홀에 도착하는 연출은 처치·보상 조건이 아니다.
- 현재 설계 방향: 처치 EXP는 HQ에 반영한다. HQ는 EXP와 Level을 가지며 크기 변화로 보여 줄 수 있다. HQ Level을 공격력과 자동으로 잇지 않는다. 구간 효과(시간 연장·적 공급)는 진행 규칙이 처리한다. 플레이어 Level은 도입하지 않는다.
- 미정: EXP 요구량과 단계, 크기 공식, HQ 크기와 생성 거리·공전 반경·시야의 관계, 다음 전투의 유지 범위, HQ HP·패배.

### 5.4 플레이어와 캐릭터(5절)

- 지금 플레이어는 1명이다. 전역에 하나뿐인 구조로 고정하지 않는다.
- 플레이어는 자기 PlayerState와 스킬을 가진다.
- 플레이어와 캐릭터는 다른 개념이다. 캐릭터는 개념상 있지만 투명하고 조작할 수 없다. 이동·피격·상호작용·스킬 기준점·추적 대상이 아니다.
- 책임이 없는 캐릭터를 위해 빈 클래스나 이동·HP 시스템을 미리 만들지 않는다.
- 장기적으로 최대 4인을 고려한다. 네트워크·복제·로비·다인 UI는 범위 밖이다.

### 5.5 패시브 스킬(6절)

- 스킬은 패시브로 발동한다. 첫 스킬은 기본 지급이며 조준점 주변 영역을 일정 간격으로 공격한다.
- 조준점은 마우스 위치에서 얻는다. 호스트가 입력을 플레이어의 조준점으로 넘긴다. Player와 스킬 규칙은 마우스를 모른다.
- 틱마다 범위 안의 적 전체에 피해를 준다. 적이 없어도 타이머는 흐르고 빈 틱은 그냥 지나간다.
- 화면의 원은 실제 공격 반경이다.
- 업그레이드로 피해량·반경·주기가 바뀐다.
- 마우스 기준은 첫 스킬의 특성이다. 모든 스킬이 마우스를 쓴다고 가정하지 않는다.
- 스킬 실행과 획득·강화는 다른 책임이다. 스킬은 피해를 요청하고 HP를 직접 덮어쓰지 않는다.
- 피해 출처 Player를 기록하되 멀티 보상 수령 규칙으로 해석하지 않는다.
- 유지 사항(18절): 첫 틱 0초, 빈 틱의 연속 진행, Player별 조준점·스킬 독립성.
- 미정: 수치, 원과 적의 겹침 판정, 조준점 부재 처리, 새 스킬 목록.

### 5.6 적과 행동(7절)

- 행성처럼 보이는 대상은 규칙상 적이다. 종류마다 기본 수치와 특성이 다르다.
- 각 적은 HP·위치·생존 등 자기 실행 상태를 가진다. 같은 종류라도 개체 상태는 공유하지 않는다.
- 적은 HQ 주변에 생성되고, 현재 행동은 HQ 주변 공전이다(플레이어 접근이 아니다).
- 행동은 적 본체와 분리하고 교체할 수 있어야 한다. 행동은 위치를 계산하고, 위치의 원본은 적이다.
- 지금은 공전 하나만 구현한다. 상태 기계·행동 전환·추적은 요구사항이 생기면 추가한다.

### 5.7 업그레이드와 실행 수치(8절)

- 구매: Gold로 업그레이드 노드를 산다. 구매 상태는 PlayerState에 기록하고 이후 전투에 반영한다. 구매는 획득 방법이며 모든 효과를 스킬로 묶지 않는다. 기준은 선행 노드와 Gold 가격이다. HQ Level에 의한 직접 해금은 아직 도입하지 않는다.
- 구매 효과와 적용 대상: 공격 피해량·범위·주기 → 스킬 실행 수치. 적 크기, HP·보상 → 적 수치·보상 계산. 적 물량, 등장 종류·비율 → 적 공급 구성. 사망 효과를 가진 적의 등장 → 적 종류와 출현 구성.
- **생성 시 계산(확정)**: 기본 정의와 실행 수치를 구분한다. 적의 실행 수치는 생성 시 기본 정의와 구매를 반영해 확정한다. 업그레이드 화면 전에 기존 적은 정리된다. 구매 효과는 이후 생성되는 적부터 적용한다. 전투 중 일시 효과는 요구사항이 생기면 정의한다.
- 크기와 질량(현재 설계 방향): 둘은 별개다. 크기는 외형과 피격 범위, 질량 증가는 HP와 보상이 함께 느는 의미로 검토한다. 독립 질량 수치는 미정이고, HP·보상 보정으로 충분하면 만들지 않는다.

### 5.8 적 공급과 진행 구간(9절)

- 현재 설계 방향: 공급은 전투 시작 배치와 HQ 성장 구간 도달 시 추가 공급을 우선 검토한다. 일정 시간마다 생성은 확정 규칙이 아니다. 공급 규칙은 언제·어떤 종류를·얼마나, 생성은 전달받은 종류·수량으로 HQ 기준 위치에 만든다. 일반 레벨업과 특정 구간 도달을 구분한다.
- 관찰·추정: 시작 배치 후 성장에 따라 시간이 늘고 적이 추가된다. 진행에 따라 종류가 늘지만 조건은 미확인이다. 특정 구간에서 주변 천체를 전부 끌어당기는 효과가 있다(처치인지 연출인지, 보상이 있는지 미확인).

### 5.9 피해·사망·보상(10절)

- HP가 0 이하가 되는 순간 사망이 확정된다. 같은 적의 사망과 보상은 한 번만 처리한다.
- 죽은 적은 이동·피해·대상 선택에 참여하지 않는다.
- 보상은 사망 때 반영한다. 흡수 연출 완료를 기다리지 않는다.
- 현재 설계 방향: Gold는 플레이어, 성장 EXP는 HQ.
- 화면에 남은 것과 규칙상 살아 있는 것은 별개다.
- 전투 공간 정리를 위한 제거는 보상이 있는 처치와 다르다.
- 지금은 단일 플레이어에게 Gold를 준다. 다인 분배는 미정이다.

### 5.10 사망 특수 효과(11절)

- 특정 적의 죽음으로 발동하는 폭발·전기·레이저 등은 적의 사망 특성으로 다룬다. 패시브 스킬(플레이어 자동 공격), 사망 효과(적의 사망이 계기), 사망 Presentation(시각 표현)을 구분한다.
- 적 종류 정의가 효과를 지정하고, 적은 자기 사망을 한 번 확정한다. 전투 처리가 대상과 피해를, 보상 처리가 보상을 한 번 반영한다. 화면은 결과를 표현할 뿐이다.
- 효과로 다른 적을 처치할 수 있고, 그 적도 같은 사망 절차(보상 1회, 사망 기록)를 따른다.
- **사망 효과는 사망 효과를 가진 적에게 피해를 주지 않는다.** 효과끼리의 연쇄는 없다(2026-09-24 확정, 레퍼런스와 같다).
- 한 단계의 효과는 대기열로 순서대로 처리한다. 재귀 호출하지 않는다.
- 첫 효과부터 적 본체 밖에 구현하되, 범용 효과 프레임워크는 미리 만들지 않는다.
- 첫 효과는 전기 연쇄 번개다(확정). 수치는 콘텐츠 값이다.
- 미정: 연쇄 처치 출처, 성장·시간 종료와 겹칠 때의 순서, 번개의 대상 선택 세부, 두 번째 이후 효과. 새 질문: 효과 수치를 구매로 강화한다면 생성 시 확정하는가.

### 5.11 Presentation과 공간(12절)

- 공격 원은 실제 반경을 읽는다. 흡수는 사망 위치에서 HQ로 이동한 뒤 View를 지우는 연출이다.
- 연출이 느리거나 생략돼도 보상은 바뀌지 않는다. 한 프레임의 여러 사망을 놓치지 않는다.
- 시각적 크기 변화와 실제 생성 공간 변화는 구분한다. 커진 HQ를 피해 생성 위치를 바꾸면 그것은 생성 규칙이다.
- 스프라이트 크기가 규칙의 원본이라고 가정하지 않는다.

### 5.12 종료와 재시작(13절)

- 전투의 시작·진행·종료와 다음 전투 조립을 구분한다. 종료 판단과 적·화면 정리는 다른 책임이다.
- 업그레이드 화면 진입 시 기존 적을 남기지 않는다. 새 전투는 구매를 반영하되 이전 적·스킬 타이머가 섞이지 않게 조립한다.
- 구매를 전투 사이에 유지하는 것과 앱 종료 후 영구 저장은 별도 결정이다.
- 미정: 종료와 공격 틱이 겹칠 때의 순서, 진행 중인 효과와 남은 흡수 연출의 처리, 일시정지 시 연출.

### 5.13 해금과 경제(14절)

- 선행 노드 해금과 가격 지불 가능 여부는 별개다.
- 구간별 예상 수입과 가격을 맞추면 HQ Level 조건 없이도 비슷한 시점에 새 능력을 사게 만들 수 있다. 레퍼런스가 이렇게 했다는 설명은 추정이다.
- 관찰한 금액(10만·50만·100만 등)을 우리 임계값으로 확정하지 않는다.

### 5.14 한 문장 기준(17절)

> HQ는 공간과 성장의 기준을 제공하고, 플레이어는 업그레이드를 소유하며, 적은 자신의 상태와 교체 가능한 행동·사망 특성을 가진다. 게임 결과는 규칙에서 확정하고 화면은 그 결과를 표현한다.

## 6. 구현이 따르는 동작

원본: [SYSTEM_CATALOG](docs/v2/SYSTEM_CATALOG.md) 2절, 각 마일스톤 결과.

**한 단계의 순서.** 한 프레임은 1/30초 이하의 단계로 나뉜다. 단계 안의 순서가 결과를 바꾸므로 계약이 순서를 지킨다.

```text
이동 → Skill(피해 → 사망 확정 → Gold·HQ EXP·Level → 사망 기록 → 효과 대기)
     → 사망 효과 → 성장 진행(공급 요청·시간 연장) → 공급된 적 생성
     → (단계 뒤) 종료 판정
```

- 성장 진행이 종료 판정보다 먼저다. 마지막 단계의 처치로 늘어난 시간이 그 판정에 들어간다.
- 공급된 적은 단계 끝에 나온다. 다음 단계부터 움직이고 맞는다.
- 사망 효과는 성장보다 먼저다. 효과 처치의 EXP가 같은 단계의 성장에 들어간다([임시] 순서).

**상태의 수명**

| 수명 | 상태 |
|---|---|
| 콘텐츠(바뀌지 않음) | 종류 정의, 노드 정의, 성장 노드, 판 시간 정의 |
| 진행(전투를 넘어 유지) | PlayerState: Gold, 산 노드 ID, 전투 잠금 |
| 전투(판마다 새로) | World, Player(조준점·Skill), HQ(EXP·Level), 적, 판 시간, 공급 대기 |
| 한 Advance | 사망 기록, 사망 효과 적중 기록. 일시정지 중에는 남는다 |

**실행 값의 확정 시점**: Skill 수치는 전투 조립 때, 적 수치·보상은 출현 때, 성장 공급량은 공급 요청 때 한 번 계산한다. 공유 정의는 바뀌지 않는다. 판 시간도 공유 정의를 바꾸지 않고 판마다의 제한 시간이 늘어난다.

**전투 흐름**: 새 진행(R) → 전투 → 시간 종료 또는 End session → 적·연출 정리 → 구매 화면 → Next battle(구매 유지). 전투 중에는 PlayerState가 잠겨 구매할 수 없고, 한 진행이 두 전투에 들어갈 수 없다. 조립은 모든 검사를 통과한 뒤에만 잠근다.

**기록과 화면**: 규칙은 사망 기록과 효과 적중 기록을 남긴다. 화면은 순번으로 한 번씩 소비한다. 화면은 결과를 결정하지 않는다.

**정책이 없는 조합은 조립 때 거부한다**: 보상이 있는 다인 판, 적·보상·공급에 영향을 주는 구매가 있는 다인 판. 처치 중에 일부만 적용되는 상황을 만들지 않으려는 것이다. 보상 없는 2인 판은 조립된다(Player 경계 계약용).

**콘텐츠 로드**: 오류를 경로와 함께 모두 모으고, 하나라도 있으면 정의를 내지 않는다. 수치 규칙은 정의 생성자 한 곳에 있다. 두 단계로 읽는다(독립 정의 → 참조 해석).

**변화가 어디까지 번지는가**(M5~M8에서 확인)

| 변화 | 바뀌는 곳 |
|---|---|
| 수치만 다른 적 종류, 성장 구간·임계값, 기존 효과 종류로 노드 추가 | 콘텐츠 데이터만 |
| 조준점을 다른 출처로 채움 | 없음 |
| 새 행동 | 행동 정의·구현, 해석기 분기, 로더의 종류 이름 |
| 새 구매 효과 종류 | 효과 종류, 대상 규칙, 적용 자리 하나 |
| 새 사망 효과 | 효과 정의, 처리 분기, 로더의 종류 이름, 화면 연출 |
| Skill 기준점 교체(실험) | 기준점 종류, Skill, 조립 순서, 로더 |
| 효과 수치를 구매로 강화(실험) | 구매 효과, 적용 자리, 적, 출현, World |

## 7. 규칙이 아닌 것 — [임시] 목록

원본: [SYSTEM_CATALOG](docs/v2/SYSTEM_CATALOG.md) 1절, [PLAN](docs/v2/PLAN.md) 7절.

**정책**

- 판은 제한 시간 하나이고 끝나면 즉시 종료한다.
- 적은 HQ에서 같은 거리, 각도 n × 간격에 나오고, 공전은 그 거리를 유지한다.
- Skill 원 안 = 적의 중심이 원 안. 조준점이 없으면 빈 틱.
- 흡수·번개 연출은 일시정지 중에도 실제 시간으로 흐른다.
- HQ EXP·Level은 전투마다 초기화한다. Gold·구매만 유지한다(레퍼런스 근거).
- 보정된 보상은 배율을 모두 곱한 뒤 올림한다.
- 선행 노드는 하나다. 효과는 콘텐츠의 노드 순서로 쌓인다.
- 번개는 중심 거리로 가장 가까운 적을 맞힌다. 같으면 목록 앞, 같은 번개는 같은 적을 한 번만 맞힌다.
- 번개 피해의 출처는 효과를 일으킨 적을 죽인 Player다(기록뿐).
- 한 단계의 효과 대기열을 모두 처리한 뒤 성장·종료를 판정한다.
- 콘텐츠는 코드로 작성한다(`SampleContent`). 저작 방식은 검증 대상이 아니다.

**샘플 값**: 판 30초(성장마다 +5초), 출현 거리 4.5, 황금각 간격, 적 3종(light·heavy·electric), aura 반경 1.2·0.5초·피해 3, 시작 light 8·heavy 2·electric 2, 성장마다 light 6·heavy 1·electric 1, 임계값 Lv2 6 ~ Lv10 126, 노드 6개, 번개 피해 10·거리 2.5·최대 3번. 표현 값은 `SamplePresentation`에 있다.

## 8. 남은 결정

원본: [GAME_RULES](docs/GAME_RULES.md) 16절.

| 주제 | 결정할 내용 |
|---|---|
| HQ 성장 | EXP 공식, 레벨·특정 구간, 전투 사이 유지 범위 |
| 공간 | HQ 외형·생성 거리·공전 반경·시야의 관계 |
| 구간 전환 | 시간 연장·적 추가·출현 종류와 도달 조건 |
| 전체 흡수 | 실제 처치인지 정리 연출인지, 보상·EXP 발생 여부 |
| 업그레이드 | 노드 목록·선행 조건·가격·강화 횟수, 여러 효과의 적용 순서 |
| 크기·질량 | 피격 범위·HP·보상의 구체적 관계 |
| 적 공급 | 시작·추가 수량, 종류 비율, 최대 적 수 |
| 스킬 | 범위 판정·수치·조준점 부재·새 스킬 |
| 사망 효과 | 두 번째 이후 효과, 연쇄 처치 출처, 번개 대상 선택 세부, 효과 강화와 생성 시 확정의 관계 |
| 종료 | 즉시 종료 세부 순서, 멀티 종료 방식 |
| 다인 보상 | Gold 분배와 HQ EXP 반영 |
| 저장 | 재화·구매·HQ 진행 중 영구 보관할 정보 |

M8이 권한 순서(여러 시스템의 인수 기준을 바꾸는 것부터):

1. HQ 유지 범위와 공간. 성장, 출현, 조립, 화면이 바뀐다.
2. 다인 보상과 구매의 합성. 조립 검사, 보상 지급, 구매 적용이 함께 바뀐다.
3. 적 공급 수량과 최대 적 수. 규모 측정의 목표가 된다.
4. 노드 목록과 가격. 노드 저작 툴의 형식과 함께 정한다.
5. 영구 저장의 범위.

## 9. 레퍼런스 게임에서 알아낸 것

원본: [REFERENCE_ANALYSIS](docs/REFERENCE_ANALYSIS.md). A Game About Feeding A Black Hole(Aarimous & Thornity, 2025-12-15, Steam app 3694480).

- 한 판은 제한 시간이 있는 짧은 세션이다. 끝나면 업그레이드 화면으로 간다. 필드의 물체는 유한하다. [공식]
- 블랙홀이 자라면 소행성이 추가되고 시간이 늘어난다. [사용자] 추가량은 트리 극초반의 노드로 늘린다. [사용자]
- 성장하면 화면에서만 커진다. 맵은 넓어지지 않는다. [공식, 플레이어]
- Level은 판마다 1부터 다시 시작하는 것으로 보인다. [추정]
- 물체는 블랙홀 주위를 돌고, 부서지면 조각으로 쪼개져 빨려 들어간다. 물질은 빨려 들어갈 때 들어온다. [플레이어]
- 공격은 커서의 원이 주기적으로 자동 피해를 준다. Damage, Radius, Speed, 치명타 업그레이드가 있다. [플레이어, 공략]
- 특수 물체: 전기(연쇄 번개), 방사능(피해 구름), 황금(돈 배율). 효과는 부서질 때 발동하고 트리로 강화한다. **특수 효과는 특수 효과를 가진 물체에 피해를 주지 못한다.** 재등장 확률 때문에 연쇄가 끝나지 않았고, 렉이 컸고, 직접 부수는 편이 재미있었기 때문이다. [공식]
- 업그레이드 트리는 영구이고 노드가 많다(메인 200개 이상). 노드 = 위치·비용·수치 보정. 구역·막으로 잠긴다. 트리는 데이터로 정의하는 것으로 보인다. [공식, 추정]
- 일정 시간마다 물체가 새로 나온다는 근거는 없다.

**우리 규칙이 일부러 다른 곳**: EXP가 들어오는 시점. 레퍼런스는 조각이 빨려 들어갈 때, 우리는 사망 확정 때다. 흡수는 연출이다.

**아직 모르는 것**: 성장 1회의 시간·소행성 기본 양, Level별 필요량 곡선, Milestone 보상, 전체 흡수의 Level과 의미, 성장과 해금의 연결, 트리 구역 잠금 조건, 피격 판정(겹치기만 해도 맞는지).

## 14. 알려진 한계와 발견

- **크기는 화면에만 쓰인다.** 피격은 적 중심 기준이다. 크기 효과를 넣으려면 겹침 규칙을 먼저 정해야 한다(판정 자리는 `PassiveSkill.IsInside` 한 곳).
- **단일 Player 보상 전제가 두 곳에 있다.** 조립 검사(`SessionAssembler`)와 지급(`World.DealDamage`). 다인 정책이 생기면 함께 바꾼다.
- **효과 적용 순서의 차이가 아직 드러나지 않는다.** 샘플에서 같은 수치에 더하기와 곱하기가 섞이지 않는다.
- **사망 효과 수치는 적 종류 정의에 고정되어 있다.** 구매로 강화하려면 출현 때 확정한 효과를 적이 가져야 한다(M8 실험 E4).
- **번개 한 번의 비용**이 적 1024마리에서 유지 프레임 하나보다 크다. 튈 때마다 전체 목록을 훑고, 죽은 적을 지울 때 목록 뒤를 당긴다.
- **연출 길이를 0으로 하면** 진행률이 첫 프레임에 0/0이 되어 위치가 NaN이 될 수 있다(코드 확인만 함). 연출 끄기는 길이와 따로 둬야 한다.
- 음수 보상 진단은 .NET 기본 예외 메시지(영문)를 쓴다. 다른 진단은 한국어다.
- M6 반경 구매의 화면 원은 코드로만 확인했다(플레이 확인 생략).

**작업 환경 주의**

- 줄 끝은 CRLF다(`core.autocrlf=true`).
- Unity가 쓰는 새 파일과 폴더에는 `.meta`가 필요하다.
- `.gitignore`의 `*.csproj`가 Unity 생성 파일을 막는다. `tests/` 아래 csproj는 `git add -f`로 추가해야 한다.
- 에디터가 열려 있으면 Unity batchmode를 쓸 수 없다.

## 15. 문서를 쓸 때 지킬 것

이 레포의 문서가 지켜 온 약속이다.

- **규칙, 관찰, [임시]를 섞지 않는다.** 레퍼런스 관찰이나 구현 편의를 게임 규칙으로 올리지 않는다. 임의로 정한 것은 [임시]로 표시하고 미정 목록에 남긴다.
- **레퍼런스로 답할 수 있는 것은 레퍼런스부터 본다.** 정할 것을 추상적인 선택지로 묻기 전에 레퍼런스를 분석한다. 레퍼런스로 답할 수 없는 것만 사람에게 묻는다.
- **미래 개념의 자리 표시자를 만들지 않는다.**
  - 조준점은 `AimPoint`다. `Player.MousePosition` 같은 이름을 쓰지 않는다.
  - 보상 귀속 규칙을 지어내지 않는다. 피해 출처는 기록일 뿐이다.
  - 책임이 없는 캐릭터에 빈 클래스를 만들지 않는다.
- **Skill은 개별 존재다.** "모든 패시브 스킬"에 붙는 효과로 묶지 않는다. 지금 액티브 스킬이 없을 뿐이다.
- **노드 저작 툴은 별도 작업이다.** 게임 쪽 문서는 노드 데이터 형식과 런타임만 다룬다.
- **담당자와 일정을 임의로 배정하지 않는다.** 목표 수량이 없으면 성능 목표를 만들지 않는다.
- **확정하지 않은 기능을 구현 완료처럼 기록하지 않는다.** 검증하지 못한 환경과 생략한 확인은 그대로 적는다.
- **완료된 기록을 소급해 고치지 않는다.** M0~M3는 당시 요구사항 기준이다. 바뀐 점은 새 기록으로 남긴다.
- 기여자는 실제 작성자로 적는다.

## 16. 용어

| 용어 | 뜻 |
|---|---|
| HQ | 중앙 블랙홀. 월드의 공간 기준점이자 성장(EXP·Level)의 주인 |
| Player | 참가자. 조준점과 Skill을 가진다. 전투마다 새로 만든다 |
| PlayerState | 전투를 넘어 유지되는 Player의 진행 데이터(Gold, 산 노드 ID, 전투 잠금) |
| 캐릭터 | 개념상 있지만 지금 게임 책임이 없는 존재. 코드에 없다 |

| 기본 정의 / 실행 수치 | 종류가 공유하는 값 / 개체가 출현 때 확정한 값(기본 + 구매 보정) |
| 조준점(AimPoint) | 첫 Skill의 기준 위치. 호스트가 마우스로 채운다 |
| Passive Skill | 자기 주기로 자동 공격하는 스킬. 첫 Skill은 조준점 주변 원 공격(aura) |
| 공급(Supply) | 무엇을 얼마나 추가할지. 전투 시작 배치와 성장 공급 |
| 출현(Spawn) | 공급받은 적을 HQ 기준 위치에 실제로 만드는 일 |
| 성장 진행 | 새로 도달한 Level의 효과(공급 요청, 시간 연장)를 한 번씩 실행하는 일 |
| 사망 효과 | 적의 죽음이 계기인 게임 효과. 첫 효과는 전기 연쇄 번개 |
| 사망 기록 / 적중 기록 | 한 Advance 동안 규칙이 남기는 결과. 화면이 순번으로 한 번씩 소비한다 |

| Advance / 단계 | 호스트의 한 프레임 진행 / 그 안에서 1/30초 이하로 나눈 규칙 진행 |
| 계약 | 규칙을 확인하는 테스트. `시스템.사례` 형식의 이름 |
| 마일스톤(M0~M8) | v2 작업 단위. PLAN 5절 |
